# AI Hotspot 搜索、RAG 与 Agent 详细设计

> 文档状态：M10 已实现，当前 RAG v3.4（2026-07-23 复核），包含证据立场/时效、分阶段计时和配置评测监控。

## 0. 当前实现结论

截图所示的“混合检索 + 重排 + 句级引用 + 评测监控”方向是正确的，但只有架构图不等于可靠 RAG。AI Hotspot 已把它落实为可审计链路：原始正文进入 Chunk，权限在召回 SQL 前置；PostgreSQL FTS 与 bge-m3 向量并行召回，RRF 融合后由 bge-reranker-v2-m3 重排；再按单一信源与事件限额做多样化，DeepSeek 只基于最终证据生成答案。每个事实句要求编号引用；覆盖低于 80%、没有引用或编号越界时，确定性降级为带引用的证据摘录，不再用第二次模型调用修复。

当前实现不引入 Elasticsearch：MVP 数据规模下 PostgreSQL `tsvector + pgvector` 已足够，并减少双写一致性与运维成本。对象存储保存采集原件，PostgreSQL 保存可查询事实、关系、Chunk、向量、运行与引用审计。

## 1. 搜索与检索链路

```text
用户/游客身份 → 解析过滤条件 → 计算可访问 dataset/object 集合
→ 权限 SQL 条件 → FTS 与 bge-m3 向量并行召回 → RRF 融合
→ bge-reranker-v2-m3 重排 → 来源/事件去重与时间、官方等级约束
→ 上下文构造 → DeepSeek 生成 → 句级引用覆盖检查/修复/降级 → 返回并留痕
```

权限过滤必须出现在召回 SQL 中。PUBLIC_RAG 对游客开放；PRIVATE_RAG 只对 ACL 命中用户。METADATA_ONLY 可用于搜索元数据但不提供正文切片；NO_INDEX 不进入任何检索索引。

## 2. 混合检索

- 查询理解输出规范化关键词、时间范围、官方/来源过滤和语义查询；当前支持问题内“过去 N 天”及 UI 7/30/90 天范围。
- FTS 与向量并行取候选并使用 RRF 融合；在线问答当前最多取 64 个候选、32 个重排结果和 8 个最终上下文，每段送模文本最多 900 字。相对分阈值会剔除与最佳证据差距过大的结果；离线黄金集仍可按评测深度扩大候选。
- 同一事件/同一来源设置上限，优先独立信源与第一方；保留发布时间和来源类型。
- 跨事件关联可扩展一跳，但必须标记扩展原因，默认不超过总上下文 25%。

## 3. 答案与引用

生成只使用提供证据；每个可核查事实带 citationId。后处理验证 citationId 存在、用户仍有权限、引用片段支持陈述。验证失败删除陈述或返回“证据不足”。答案保存检索过滤、候选 ID、Rerank 分、引用和权限快照，便于复现。

防提示注入：正文以数据块传入；禁止执行正文中的命令；系统/开发者指令不暴露；外链内容不能改变工具权限。涉及未证实信息时答案明确标注；DEBUNKED 默认不参与，用户明确研究辟谣时单独展示。

RAG v3.3 将两个容易混淆的维度分开保存：`citation.support_status` 只描述引用片段对答案句的支撑质量；`evidence_assessment.evidence_stance` 描述证据对统一主张是支持、反驳还是未证实，`freshness_status` 独立描述当前、过期或时间未知。Generation 以结构化 JSON 给出初判，Core 再执行不可绕过的治理规则：未确认内容强制为未证实；对时间敏感问题，超出时间窗口的证据标为过期；明确否认原主张的文本标为反驳。

V041 起增加 Claim-Evidence 蕴含门禁：服务端提取中英文实体、数字和中文双字信号，对模型生成的 `claimText` 与数据库原文做覆盖校验；完全不匹配的 SUPPORTS 强制降级为 UNVERIFIED，并以 `ENTAILMENT_GUARD` 留痕。该分数是防止明显幻觉支持关系的确定性下限，不冒充完整语义事实判定。引用 URL 不接受模型输出，只能由已入库的 Chunk → Document → SourceEntity 关系返回；评测要求当前 Prompt 的引用来源链异常为 0。

在线结构质量不允许用“0 样本、0 失败”通过：当前 Prompt 至少需要 6 条真实 Provider 结构样本和 6 条 Claim-Evidence 样本。生成结果必须是完整 JSON、包含非空 answer 和实际引用编号对应的 evidenceAssessments；截断或合同不完整时只使用确定性原文摘录，不把残缺 JSON 当成答案。V042 将 `rag-answer-v1.2.1` 的正文和 assessment 长度做上限约束，并按上下文数量动态给出输出预算。

冲突检测以标准化后的同一主张为边界，只有同一主张同时具备支持和反驳证据才显示冲突提示，避免把不同事实的相反立场误报为冲突。未证实、过期和冲突证据都会在答案中补充带编号的披露，新增引用仍须通过 ACL 和编号校验；前端分别展示语义立场与时效徽标，点击正文编号可聚焦原始证据卡。

## 4. Agent 架构

Agent 由 Planner、Policy Gate、Tool Executor、State Store 和 Result Composer 组成。MVP 工具：搜索公开/有权内容、读取内容/事件/主题、创建研究报告草稿、创建/修改本人订阅、查看采集状态；信源修改、发布、下架、重放等运营写工具仅 OPERATOR/ADMIN 且按风险审批。

工具使用 JSON Schema，限制字段、目标范围、超时和返回大小。Agent 无通用 Shell、数据库、任意 HTTP 或密钥读取工具。所有调用记录 caller、run、step、tool、参数 Hash、对象版本、结果摘要和 traceId。

## 5. 风险分级

| 等级 | 示例 | 处理 |
|---|---|---|
| L0 | 搜索、读取公开内容 | 自动 |
| L1 | 创建本人草稿/订阅 | 自动并可撤销 |
| L2 | 暂停 Endpoint、重试任务 | 操作前确认/按角色审批 |
| L3 | 发布、下架、批量重放、角色变更 | 独立审批，MVP 不允许无人值守 |
| 禁止 | 密钥读取、任意代码、绕过权限 | 永不执行 |

## 6. 失败与恢复

每步可重试但外部写操作先查幂等结果；运行支持取消和超时。失败返回已完成步骤、未完成原因和可安全重试入口。模型不可用时 Planner 可失败，但不能绕过 Policy Gate；审批过期或参数变化必须重新申请。

AGENT-01 将上述原则落实到当前单步状态机。运行记录先独立提交并立即向客户端返回 runId，再由有界后台执行器越过工具执行边界，因此另一个请求可以在长时间研究调用期间设置取消；执行器固定 2 个核心线程、最多 4 个线程和 100 个排队任务，拒绝继续堆积时将运行标记为可观察失败。完成回写只允许覆盖仍为 `RUNNING` 的运行。取消会同时收敛待审批、未开始步骤和工具，已经开始的写工具标记为“结果不确定”而不是声称回滚。审批维护每 15 秒执行，过期审批连同运行、步骤和工具一起进入终态；运行心跳超过 5 分钟视为进程中断。

重试不复活或覆盖旧记录，而是通过 `retry_of_run_id + attempt_no` 从原始目标创建新运行，最多三次。已有成功工具调用不可重试；订阅等写工具一旦记录 `started_at`，即使进程中断也禁止自动重试，避免重复副作用。审批通过前同时复核审批参数 Hash、工具参数 Hash、当前目标 Hash、审批人的实时权限和发起人的实时权限；权限降低、账号停用或参数变化都会拒绝旧审批。创建时的 `permission_snapshot` 只用于审计，不能替代执行前实时授权。

## 7. 验收

- 构造跨用户 PRIVATE_RAG 测试，召回结果为零且日志不泄露标题。
- 引用点击能定位真实内容/片段；无证据问题明确拒答。
- 恶意网页提示不能改变系统指令或调用工具。
- Agent 参数变化使旧审批无效；取消运行后不再开始新步骤。
- Mock Provider 无 Key 完整跑通开发验收。

## 8. 配置、评测与监控

管理端“模型接入与 RAG 运行中心”拆成三个任务页签：模型接入负责厂商连接、烟测和任务路由；RAG 监控负责延迟、Token、错误、证据和慢查询；质量评测负责黄金集、真实失败反馈与发布门禁。平台连接支持环境变量引用或 AES-GCM 加密凭据，任何 API 都不返回原始密钥、密文、nonce 或指纹。动态连接只允许 Core 使用内部令牌传给 AI API，浏览器客户端不能直接提交 Provider 覆盖。

V045 为未来用户 BYOK 建立独立 `provider_connection.owner_user_id` 与 `user_provider_assignment`。每个任务运行时先选择当前用户已启用的私有路由，否则回落到平台路由；`provider_metric` 同时记录连接、使用者、查询运行和凭据归属，因此能分别统计“平台 Token”和“用户 Token”。当前用户表无数据，用户 CRUD、配额、撤销和滥用防护完成前不开放入口。

RAG-04 将监控按运营决策分层：顶部展示查询量、总延迟 P95、引用覆盖、Provider 错误率和成本状态；中层展示 Embedding、混合召回、Rerank、Generation 的均值/P95及小时趋势；下层展示 Provider 调用/Token、无证据原因、索引护栏、慢查询样本和可筛选评测历史。观察窗口统一支持 24/72/168 小时，卡片、趋势和明细使用相同时间边界。

新产生的 `NO_EVIDENCE` 运行在 `retrieval_diagnostics.noEvidenceReason` 记录官方范围、时间范围、来源类型、无相关 Chunk、重排无结果或多样化过滤原因；历史记录不反推原因，只显示 `LEGACY_UNCLASSIFIED`。Generation API 透传上游实际 input/output Token，Core 将成功或失败、耗时、Token 和安全错误码写入 `provider_metric`。成本只在 `RAG_GENERATION.parameters` 明确配置 `inputCostPerMillion` 与 `outputCostPerMillion` 后估算；未配置时界面显示“待配置”。

监控至少包含：24 小时 RAG 查询数、成功/无证据数、平均与 P95 延迟、平均引用覆盖率、平均独立信源数、平均上下文数、已索引文档、Chunk/向量完整率、索引信源数和缺失原始发布时间数。黄金集门禁同时检查 Recall@20、nDCG、近 7 日实际引用支持率（至少 90%）、真实答案句级引用覆盖率（至少 80%）、信源多样性、Mock 公开泄漏和 ACL 泄漏。检索到但未被答案引用的上下文属于候选证据，不写成 `research.citation`，也不进入引用支持率分母；引用支持与答案句级覆盖仍是两个独立指标。

2026-07-20 实际回归问题“过去30天 Agent 产品有哪些值得关注的变化”返回 10 条引用、6 个独立信源、7 条官方/一手证据，句级引用覆盖率 0.875；这是一条当前环境实测记录，不是固定性能承诺。

RAG v3.1 黄金集包含 50 条中文主问题，分为 20 条主题、8 条官方限定、7 条时间过滤、5 条中英混合、5 条多信源/多跳、3 条预期无证据和 2 条 ACL 公开边界，并以标签标识冲突类问题。`input_data` 的过滤条件会真实进入检索规划，`expected_data` 同时校验命中、独立信源数、官方等级、发布时间窗口、公开范围和无证据结果。2026-07-22 真实回归 Recall@20=1.0、nDCG@10=0.974，50 条均无约束违规，引用支持率门槛保持 0.95。RAG v3.3 已把这些冲突场景扩展到答案级、引用级表达与审计。

RAG v3.2 在每个查询的 `retrieval_diagnostics.stageTimingsMs` 中记录查询理解、权限/会话、Embedding、混合召回、Rerank、去重、生成、引用校验、引用兜底、持久化和总耗时；管理指标同时聚合主要阶段均值。2026-07-22 使用当前真实公开库和真实 Provider 连续执行 12 条不同问题，平均 7.683 秒、P95/最大值 8.835 秒，引用修复额外网络耗时为 0，所有样本至少返回 2 个落库引用。

RAG-05 复核确认 7 天 19.490 秒 P95 混合了旧 80/80 候选、40 重排、10 上下文且无阶段计时的历史运行。按当前 64/64、32、8 配置和阶段计时筛选后，88 条可比成功样本平均 8.754 秒、P95 11.651 秒；固定 12 题真实 Provider 回归平均 8.062 秒、P95/最大 10.530 秒，全部成功且每题至少 2 条引用。管理端同时显示当前配置可比 P95 和全窗口历史 P95；任何窗口必须标明样本量、配置版本、Provider 与时间边界，不再跨代混写。

RAG-06 通过 V033～V035 完成阶段 A 核心：57 条黄金集按 DEV/TEST/CANARY 分层并增加 Hit@5、Precision@8、MRR@10、拒答和结构化输出门禁；System/Task/Evidence 模板进入数据库版本、Hash 和查询追踪；三类 Provider 使用独立超时、结构化错误码和一次幂等重试。真实 ALL 回归 Recall@20=1.0、nDCG@10=0.977、Hit@5=1.0、Precision@8=0.890、MRR@10=0.963、拒答准确率=1.0，三个 split 全部通过、ACL 泄漏=0。

后续命中率、召回率、回答正确性、Prompt 与技术栈演进统一按 [RAG 成熟化优化方案](./RAG成熟化优化方案.md) 执行。

研究工作台把这些诊断直接呈现为六阶段时间轴，并采用“筛选轻栏—答案主画布—引用证据栏”的连续布局。提交期间逐阶段显示运行态，完成后显示真实毫秒值；正文编号引用可聚焦对应证据卡。动画只用于状态变化与结果进入，系统请求减少动态效果时全部停用。
