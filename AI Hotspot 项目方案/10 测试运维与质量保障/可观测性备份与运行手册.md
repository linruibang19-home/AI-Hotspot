# AI Hotspot 可观测性、备份与运行手册

> 文档状态：M0 冻结候选。

## 1. 可观测性

全链路传播 `requestId/correlationId/traceId`。结构化日志按服务、环境、版本、用户匿名 ID、对象和错误码检索；禁止密钥、Cookie、完整私有正文和未脱敏邮箱。

指标分四类：

- 产品：公开内容、精选、订阅、邮件、RAG/Agent 成功率。
- 服务：请求率、错误率、P50/P95/P99、线程/连接池。
- 流水线：采集成功、提取、审核、队列、Outbox/Inbox、DLQ、模型成本。
- 基础设施：CPU、内存、磁盘、容器重启、Postgres/Redis/RabbitMQ/MinIO 容量。

告警必须有严重级别、阈值、持续时间、负责人和 Runbook；避免只有“服务挂了”无诊断信息。

## 2. 健康检查

`/health/live` 只判断进程；`/health/ready` 检查关键依赖但设短超时；`/health/detail` 仅管理网络。Worker 写心跳；Provider 健康不应让公开只读站点整体不 Ready，而应显示能力降级。

## 3. 备份与恢复

- PostgreSQL 每日全量 + WAL/增量策略，目标 RPO 24h（Beta 前评估缩短）、RTO 4h。
- MinIO 备份对象和版本；配置、Nginx、Compose、迁移与模板在 Git。
- Redis/RabbitMQ 不作为唯一业务真相；持久化用于提高恢复，不替代数据库状态。
- 每月至少一次恢复演练：新环境恢复 → 迁移 → 对象校验 → 权限/下架/索引对账 → 抽样 E2E。

备份加密、限制访问、设置保留；恢复演练记录耗时和缺陷。恢复后先管理模式，完成对账再开放。

## 4. 常用 Runbook

- 队列积压：确认消费者/Provider → 降低非关键任务 → 扩 Worker → 检查 DLQ，禁止盲目清空。
- Outbox 滞留：检查 RabbitMQ/Confirm/数据库锁 → 恢复 Publisher → 观察最老事件。
- 采集异常：按 Endpoint 隔离暂停 → 检查结构/限流/策略 → 试探 → 受控恢复。
- 模型故障：切 Mock/回退只用于开发；生产暂停 AI 发布、保留采集 → 恢复后补处理。
- 邮件故障：暂停发送 Worker但保留 Run → 修复 SMTP → 根据 message_key 重试。
- 磁盘告警：阻止大对象新写入 → 清理符合保留期对象 → 扩容；禁止直接删数据库文件。
- 安全事件：隔离、轮换、审计、索引/缓存清理、复盘。

## 5. 部署与回滚

Docker Compose 是唯一标准运行方式。镜像使用不可变版本；部署顺序为备份/检查 → 向前兼容迁移 → 服务 → Worker → 冒烟；回滚应用镜像前验证数据库兼容。破坏性 Schema 采用 expand/migrate/contract 多版本流程。

## 6. Beta 上线清单

HTTPS、域名与合规评估；管理员初始密码轮换；公开注册关闭；密钥和备份验证；邮件退订测试；阈值/Provider/预算确认；告警可到达；恢复演练通过；隐私/版权/反馈入口可用；版本和变更日志发布。
