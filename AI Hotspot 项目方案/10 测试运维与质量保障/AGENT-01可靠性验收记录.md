# AGENT-01 可靠性验收记录

> 验收时间：2026-07-25
>
> 运行标准：Docker Compose
>
> 数据来源：本地真实 PostgreSQL、Core API、AI API 与 Web

## 1. 验收结论

AGENT-01 通过。既有四类 Agent 保持不变，运行创建改为先持久化并立即返回 `runId`，工具由有界执行器异步执行；取消、审批过期、进程中断、安全重试、权限复核和用量留痕均形成可审计闭环。此次没有引入 LangGraph 或新的中间件，也没有把单机执行器描述成分布式调度系统。

## 2. 状态机与数据交付

V038 为 `automation.agent_run` 增加重试链、尝试次数、权限快照、结构化失败码、取消时间、心跳和估算成本，为 `automation.tool_call` 增加开始及完成时间，并建立恢复与重试索引。

| 场景 | 收敛结果 |
|---|---|
| 待审批运行取消 | Run `CANCELLED`、Step `SKIPPED`、Tool `DENIED`、Approval `REJECTED` |
| 审批过期 | Run `CANCELLED/APPROVAL_EXPIRED`、Step `SKIPPED`、Tool `DENIED`、Approval `EXPIRED` |
| 长工具执行中取消 | `runId` 立即可得；取消后工具返回不能覆盖 `CANCELLED` 终态 |
| 进程中断 | 心跳超过 5 分钟的运行收敛为 `FAILED/EXECUTION_INTERRUPTED` |
| 安全重试 | 创建关联的新 Run，不覆盖旧运行；最多 3 次尝试 |
| 写边界不确定 | 已开始的订阅写操作禁止自动重试 |
| 审批执行 | 重新校验输入 Hash、目标 Hash、工具 Hash、发起人当前权限和审批人当前权限 |
| 普通用户 | 只能发现和启动 RESEARCH、SUBSCRIPTION；高风险启动返回 403 |

生命周期维护每 15 秒执行一次，使用行锁和 `SKIP LOCKED` 避免并发维护器重复收敛和重复审计；未安装 Agent Schema 的精简测试环境会安全跳过维护。

## 3. 真实 API 验收证据

| 检查 | 结果 |

## 5. 工作台交付

Agent 工作台现在提供运行状态定时刷新、运行详情、步骤/工具/审批时间线、失败码、尝试次数、Token、成本配置状态、取消和安全重试。表格及详情字号统一提升，失败与审批状态不再只依赖英文枚举理解。

## 6. 已知边界

1. 当前是单 Core 实例内的有界执行器，数据库负责持久化与中断恢复；它不等同于跨节点任务调度。只有目标环境证明需要水平扩容时，才评估 RabbitMQ Agent Worker 或独立调度服务。
2. 取消是协作式取消。已经向外部 Provider 发出的请求不能强制撤回，因此工具结果不确定时会保守标记失败，并禁止不安全写操作重试。
3. Provider Token 单价尚未配置，因此成本只保留真实用量和“待配置”状态；不得用猜测单价生成金额。
4. 多步骤复杂任务质量、并发容量和生产故障注入仍需目标环境与真实任务样本，不在本地验收中虚构结论。
