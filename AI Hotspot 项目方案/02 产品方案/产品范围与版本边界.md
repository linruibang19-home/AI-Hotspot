# AI Hotspot 产品范围与版本边界

> 文档状态：草案

## 1. MVP 定义

AI Hotspot 的 MVP 是一个在本地电脑上可完整运行的真实产品闭环，不是静态演示。但“完整”指核心领域均可使用，不代表首版覆盖所有信源、所有模型和所有高级能力。

## 2. MVP 必须包含

### 2.1 内容发现

- 精选；
- 全部动态；
- 当前热点；
- AI 日报；
- 主题列表和主题详情；
- 内容详情；
- 事件详情；
- 全局搜索；
- 收藏；
- 基础筛选、分页和排序。
- 游客可访问全部公开内容页面和公开搜索；
- 普通用户可通过邮箱验证码注册与登录；登录用户可使用收藏、订阅、RAG 和 Agent。

### 2.2 信源与采集

- SourceEntity 和 SourceEndpoint 管理；
- RSS/Atom；
- Sitemap 与普通网站；
- GitHub Releases；
- arXiv；
- Hacker News 官方 API；
- Hugging Face 公开页面或 Feed；
- OpenReview；
- 手工 URL；
- 信源试抓取、启用、暂停、重试和健康监控。

### 2.3 内容处理

- 采集原件保存；
- 原始条目拆分；
- URL 规范化；
- 正文抽取；
- 语言识别；
- 中文标题和摘要；
- 分类、标签和实体；
- 事实类型识别；
- 内容评分和推荐理由；
- 精确去重和近重复检测；
- 事件创建、聚类和跨事件关联；
- 人工审核和纠正。
- PUBLISHED/PUBLIC 准入控制；
- UNCONFIRMED 降权标记和 DEBUNKED 默认移除；
- 展示策略与索引策略分离；
- 纠错、下架、恢复和工单审计。

### 2.4 搜索与知识研究

- PostgreSQL 全文搜索；
- pgvector 语义检索；
- 元数据过滤；
- 混合召回；
- 事件级折叠；
- Rerank；
- RAG 流式回答；
- 证据面板；
- 引用验证；
- 对话和研究记录；
- 问答、对比和时间线三种输出模式。

### 2.5 Agent

- Research Agent；
- Subscription Agent；
- Source Operations Agent；
- Crawler Operations Agent；
- Agent 运行和步骤；
- 工具权限；
- 人工审批；
- 取消、失败和重试；
- Token、费用和延迟记录。

### 2.6 订阅和邮件

- 结构化创建订阅；
- 自然语言解析订阅；
- 创建前预览和确认；
- 每日定时运行；
- 每周定时运行；
- 邮件模板；
- 本地 Mailpit 验证；
- SMTP 可配置；
- 投递状态和失败重试。
- 一键退订和订阅偏好入口。

### 2.7 管理与治理

- 用户与角色基础能力；
- 公众邮箱验证码注册、验证码登录；
- 管理员引导账号、角色管理和可选邀请码；
- 信源管理；
- 采集监控；
- 内容审核；
- 事件审核；
- 日报管理；
- 模型与 Prompt 配置；
- Agent 审批；
- 审计日志；
- 失败任务、死信任务查看和人工重放；
- 系统设置和健康状态。

### 2.8 工程能力

- Next.js、Spring Boot、FastAPI；
- PostgreSQL + pgvector；
- Redis；
- RabbitMQ；
- MinIO；
- Docker Compose；
- 数据库迁移；
- OpenAPI；
- 结构化日志和 trace_id；
- Transactional Outbox 与 Consumer Inbox；
- 单元、集成和端到端测试；
- 本地启动、备份和恢复说明。

## 3. MVP 明确不包含

- X API、X 登录态、非公开接口或自动采集；
- 微信公众号扫码授权、自动订阅、登录态采集或批量发现；
- WeChat Collector 和 WeRSS；
- 人工复制 X 或公众号 URL 作为核心产品能力；
- 付费墙绕过；
- YouTube 全量字幕采集；
- Reddit 自动采集；
- 无限制开放网页爬取；
- 多 Agent 自由讨论；
- Agent 任意 Shell 或数据库权限；
- 无人工确认的删除、发布、全站推送和批量修改；
- Kafka、Kubernetes、Elasticsearch/OpenSearch；
- 使用 Redis List 或 Redis Streams 代替 RabbitMQ 核心任务队列；
- 多区域高可用和互联网规模部署；
- 移动 App；
- 商业支付和套餐系统；
- 完整公开开发者平台。

## 4. MVP 内部交付顺序

```text
M0 产品方案与正式原型
M1 本地工程与身份权限
M2 RSS 真实垂直闭环
M3 多 Connector 与采集运营
M4 内容质量、事件和日报
M5 搜索、RAG 和引用
M6 订阅、邮件和 Agent
M7 完整验收与连续运行
```

每个里程碑必须产出可运行功能，不允许长期并行建设多个未闭环模块。

## 5. 版本边界判断规则

一个需求只有同时满足以下条件才进入 MVP：

1. 对核心用户价值有直接贡献；
2. 是完整业务闭环所必需；
3. 能在本地环境可靠运行；
4. 可以定义明确验收条件；
5. 不依赖高风险、非公开或不可持续的数据来源。

不满足上述条件的需求进入后续版本或实验清单。

- 月报和多模板报告；
- 飞书、Slack 等更多推送；
- 用户自定义主题和共享研究；
- 对外 RSS、REST API 和 Agent Skill；
- 浏览器扩展；
- 个性化推荐；
- 团队空间和多租户；
- 公开 Beta 和云端部署；
- 更完整的邮箱域名风控、设备风控和管理员 MFA；
- 更复杂的评测和模型路由。
