# AI Hotspot 目标用户与使用场景

> 文档状态：已确认。MVP 面向个人用户开放邮箱验证码注册和登录，管理能力仍由独立管理员账号控制。

## 1. 目标用户分层

### 1.1 核心用户：AI 开发者与技术负责人

关注内容：

- 模型和 API 更新；
- Agent、RAG、MCP、推理和部署；
- GitHub Release 与开源项目；
- 技术论文和工程实践；
- 安全问题和成本变化。

主要需求：快速发现变化、评估技术影响、查找原始资料、形成技术选型依据。

### 1.2 核心用户：AI 产品经理与创业团队

关注内容：

- AI 产品更新；
- 用户体验和商业模式；
- 国内外厂商路线；
- 行业应用和竞争变化；
- 重点公司与模型动态。

主要需求：掌握竞品、发现产品机会、生成对比和趋势报告。

### 1.3 重要用户：研究、媒体与投资分析人员

关注内容：

- 论文和研究机构；
- 公司战略与人事；
- 融资、并购和政策；
- 事件时间线；
- 来源冲突和独立印证。

主要需求：回溯事件、核实来源、生成有引用的研究材料。

### 1.4 运营用户：内容编辑与信源运营

主要任务：

- 维护信源；
- 处理采集失败；
- 审核摘要、分类和评分；
- 合并、拆分和跨事件关联；
- 编辑日报；
- 管理邮件推送；
- 纠正 AI 结果。

### 1.5 系统管理员

主要任务：

- 配置用户、角色和权限；
- 管理模型、Prompt 和费用预算；
- 审批 Agent 高风险操作；
- 查看审计、安全、任务积压和系统健康。

## 2. 用户角色

| 角色 | 主要能力 |
|---|---|
| 游客 | 无需登录浏览精选、全部公开动态、日报、主题、公开内容详情和公开搜索 |
| 注册用户 | 通过邮箱验证码自行注册或登录，使用收藏、订阅、研究问答、Agent 和研究记录 |
| 编辑 | 修改内容结构化结果、精选状态和事件关系 |
| OPERATOR | 新增和维护信源、试抓取、运行采集并处理运营失败 |
| ADMIN | 邀请账号、用户权限、模型、Prompt、全站发布、推送、审批和审计 |
| 系统 Agent | 仅通过授权工具在调用者权限范围内工作 |

普通用户在 MVP 中不能新增或修改信源。用户推荐信源属于后续能力，且未来推荐也不得自动进入采集和公开流程。

## 3. 核心使用场景

### 场景一：每天快速了解 AI 变化

用户打开精选页，在 5～10 分钟内查看热点、精选内容和推荐理由。用户可以按模型、产品、行业、论文和技巧筛选，并打开事件或原文深入阅读。

成功标准：无需浏览多个外部站点即可识别当天最重要的独立事件。

### 场景二：追踪某个主题或公司

用户进入“Agent 智能体”“OpenAI”或“多模态”等主题，查看近期事件、内容趋势、主要实体和精选内容，并创建持续订阅。

成功标准：用户能看到长期变化，而不是一次性关键词搜索结果。

### 场景三：核实一条行业消息

用户从热点或搜索进入事件详情，查看主条目、官方来源、其他独立信源、媒体解读和社区观点。

成功标准：用户可以分辨事实、转述和观点，并找到原始来源。

### 场景四：进行时间范围研究

用户提问：“过去 30 天 OpenAI 和 Anthropic 在 Coding Agent 上有哪些变化？”系统解析时间、实体和主题，执行混合检索和事件折叠，返回带引用的对比结果。

成功标准：所有重要结论均有当前知识库证据，过滤条件严格生效。

### 场景五：通过邮件持续关注

用户使用自然语言或结构化表单创建订阅，例如每天上午 9 点发送过去 24 小时 Agent 和 AI 编码方向最重要的 10 条内容。

成功标准：创建前可预览结构化规则，邮件内容可追溯到站内事件和原文。

### 场景六：管理员新增信源

管理员提交 URL，系统识别入口类型、检查重复、试抓取、评估可提取性和更新频率，推荐 Connector、采集周期、来源等级和内容策略。

成功标准：试抓取不污染公开内容，确认后才启用正式采集。

### 场景七：处理错误事件关联

编辑在审核队列中发现一篇文章同时讨论多个发布事项，将其关联到多个事件，调整关系类型，并选择各事件主条目。

成功标准：修改有理由、有操作者、有审计记录，可用于后续评测。

### 场景八：Agent 完成研究任务

用户创建研究任务，Agent 使用受控搜索、证据、比较和报告工具生成结果。若任务只读则直接执行；若涉及创建订阅、修改信源或发布，则进入审批。

成功标准：运行过程、工具、引用、费用和审批均可查看。

## 4. 用户体验目标

- 新用户无需阅读说明即可浏览精选；
- 高频用户能够通过键盘、筛选和收藏快速处理信息；
- 研究用户始终能看到证据和过滤范围；
- 运营用户能从异常直接定位信源、任务、原件和处理步骤；
- 管理员能清楚判断 Agent 准备执行的具体写操作。

## 5. 待验证假设

- 核心用户更重视信息可信度而不是内容数量；
- 推荐理由比泛化摘要更能帮助用户判断价值；
- 事件级组织比文章列表更适合研究和热点；
- 邮件日报是本地产品首个足够有效的推送方式；
- 用户愿意通过来源等级和时间范围限制 RAG；
- 运营人员能够接受低置信度内容进入审核队列。
