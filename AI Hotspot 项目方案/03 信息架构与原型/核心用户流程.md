# AI Hotspot 核心用户流程

> 文档状态：草案

## 1. 浏览精选与热点

### 目标

用户在短时间内了解近期最重要的 AI 行业变化。游客无需登录即可完成浏览、搜索和阅读公开详情；收藏、订阅和研究操作会引导其使用邀请制账号登录。

### 主流程

```text
进入精选页
→ 查看当前热点
→ 选择全部/模型/产品/行业/论文/技巧
→ 浏览日期时间线
→ 阅读摘要和推荐理由
→ 打开内容详情或事件详情
→ 查看来源、其他信源和原文
→ 收藏、研究或创建订阅
```

### 异常和边界

- 当天无精选：展示最近更新时间、全部动态入口和历史日报；
- 部分内容加载失败：保留已加载内容并允许重试；
- 内容已下架：详情页展示下架状态，不继续提供正文；
- 未登录收藏：引导登录，并在成功后返回当前内容。

## 2. 搜索并核实消息

### 目标

确认一条消息是否真实、来源是什么、是否有独立报道。

### 主流程

```text
输入关键词
→ 系统搜索内容、事件、主题和实体
→ 用户设置时间和来源范围
→ 查看事件优先结果
→ 进入事件详情
→ 查看主条目和独立信源
→ 区分官方、研究、报道、观点和传闻
→ 打开原文或发起研究
```

### 关键规则

- 同事件的重复报道在结果中折叠；
- 用户可以展开所有相关内容；
- 搜索结果必须显示对象类型；
- 传闻或未证实内容需要明显标记。

## 3. 通过主题持续追踪

```text
进入主题页
→ 选择公司/模型、技术方向或内容形态
→ 查看主题定义和趋势
→ 查看近期热点事件和精选内容
→ 选择主要实体或时间范围
→ 创建订阅或发起研究
```

创建订阅时继承当前主题，但允许用户修改来源等级、频率和最大条数。

## 4. 创建 RAG 研究

### 主流程

```text
从研究页、内容、事件、主题或搜索发起研究
→ 输入问题
→ 设置或继承时间、主题、实体、来源和语言
→ 系统解析查询意图
→ 用户确认或修改解析结果
→ 执行全文与向量混合检索
→ 事件级折叠和重排序
→ 流式生成回答
→ 显示证据和引用
→ 引用验证
→ 保存、追问、导出或转为订阅
```

### 资料不足

```text
证据不足
→ 明确说明缺少哪类资料
→ 展示已找到的有限证据
→ 建议扩大时间、主题或来源范围
→ 用户确认后重新检索
```

系统不得静默使用模型训练记忆补齐答案。

## 5. 创建邮件订阅

### 自然语言流程

```text
用户输入订阅需求
→ Subscription Agent 解析
→ 生成结构化条件
→ 展示名称、主题、来源、窗口、频率、时区和条数
→ 用户修改并确认
→ 创建订阅
→ 到期执行检索与事件折叠
→ 生成邮件预览
→ 发送
→ 保存投递记录
```

MVP 允许每日和每周简报，默认时区为 Asia/Shanghai，不支持即时推送。邮件必须包含一键退订和偏好入口。

### 异常流程

- 需求含糊：只询问最关键的一个问题；
- 没有匹配内容：按用户设置决定不发送或发送“暂无更新”；
- SMTP 失败：记录错误并按策略重试；
- 重复运行：通过幂等键禁止重复发送。

## 6. 管理员新增信源

只有 ADMIN 和 OPERATOR 可以执行该流程。普通用户推荐信源不属于 MVP。

```text
进入信源管理
→ 输入 URL 或选择导入
→ 检查 URL 安全
→ 检查重复主体和入口
→ 自动发现 RSS/Sitemap/页面类型
→ 试抓取样本
→ 检查列表、正文、时间、语言和更新频率
→ 推荐 Connector、周期、来源等级和内容策略
→ 管理员查看样本和风险
→ 确认创建主体或绑定已有主体
→ 确认启用入口
→ 创建首次正式采集任务
```

### 失败处理

- URL 不安全：拒绝访问并说明原因；
- 无法识别：允许选择 Connector 或配置受控规则；
- 正文置信度低：可以保存为停用状态，不进入正式采集；
- 已存在：跳转现有入口，不重复创建。

## 7. 内容采集与处理

```text
调度创建采集任务
→ Connector 获取响应
→ 保存采集原件
→ 拆分原始条目
→ URL 和外部 ID 精确去重
→ 正文提取
→ 创建内容条目
→ AI 摘要、分类、实体、事实类型和推荐理由
→ 分项评分
→ 近重复检测
→ 事件候选和跨事件关联
→ 人工审核或自动通过
→ 知识切片和索引
→ 进入全部动态、精选候选或隐藏池
```

只有满足公开准入规则并最终处于 `PUBLISHED + PUBLIC` 的内容才能进入公开“全部动态”。未证实内容按 `UNCONFIRMED` 规则标记和降权，已证伪内容标记 `DEBUNKED` 并从默认结果移除。

任何失败都必须保留上一个成功阶段，支持从失败步骤恢复，而不是重新抓取全部数据。

## 8. 编辑审核内容

```text
打开审核队列
→ 按问题类型和置信度筛选
→ 查看原文、原始提取和 AI 输出
→ 修改标题、摘要、分类、实体、评分或可见性
→ 填写修改理由
→ 保存并触发受影响的去重、事件或索引任务
→ 生成审计记录和纠正样本
```

## 9. 编辑审核事件

### 跨事件关联

```text
打开候选内容
→ 查看 AI 推荐的多个事件
→ 分别设置关联角色和置信度
→ 选择是否创建新事件
→ 确认主条目和事件摘要
→ 保存关联
→ 更新事件热度、时间线和索引
```

### 合并事件

合并前展示成员、主条目、主题和引用影响；合并后保留旧事件跳转和审计记录。

### 拆分事件

拆分前选择要迁移的内容关联；拆分后重新计算两个事件的主条目、热度和摘要。

## 10. Agent 研究任务

```text
用户选择 Research Agent
→ 输入目标和限制
→ Agent 生成计划
→ 调用搜索、证据、比较和时间线工具
→ 生成带引用报告
→ 引用验证
→ 展示结果、步骤、费用和耗时
```

只读研究不需要逐步审批，但用户可以取消运行。

## 11. Agent 高风险操作

```text
Agent 准备调用写工具
→ 服务端校验调用者权限
→ 创建绑定具体参数的审批请求
→ 运行进入等待审批
→ 管理员查看影响、差异和风险
→ 批准或拒绝
→ 批准后使用审批凭证执行一次
→ 保存工具结果和审计
```

审批后参数发生变化时，原审批失效并重新申请。

## 12. 日报生成与邮件发送

```text
日报调度触发
→ 查询时间窗口内事件
→ 按来源、影响、热度和主题选择候选
→ 生成日报草稿
→ 编辑审核
→ 发布站内日报
→ 生成邮件版本
→ 发送订阅用户
→ 保存内容快照和投递结果
```

是否允许无人审核自动发布将在后续确认。首版默认支持人工审核后发布。

## 13. 内容下架

```text
管理员选择内容、URL、信源主体或入口
→ 查看影响范围
→ 填写原因
→ 确认高风险操作
→ 公开页面隐藏
→ 搜索与向量索引不可检索
→ 缓存失效
→ 事件重新计算
→ 保留最小审计信息
```

下架来源可以是管理员主动操作，也可以来自用户纠错或下架反馈形成的管理工单。恢复同样需要权限和审计。

## 14. 邀请制注册与登录

```text
管理员创建账号或邀请码
→ 用户通过邀请入口注册
→ 验证邀请有效性和使用状态
→ 创建用户并分配默认角色
→ 登录
→ 使用收藏、订阅、RAG 和 Agent
```

公众自由注册默认关闭。未来开启必须通过配置和安全评审，不改变现有邀请机制。

## 15. 流程设计检查项

每个后续页面和接口必须能够回答：

- 当前操作属于哪个流程；
- 谁可以执行；
- 输入是什么；
- 成功后影响哪些对象；
- 失败能否恢复；
- 是否需要审批；
- 是否生成审计；
- 用户如何确认结果。
