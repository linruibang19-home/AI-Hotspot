# AI Hotspot 页面状态、交互与组件规范

> 文档状态：M0 冻结候选；原型和正式前端共同遵守。

## 1. 状态合同

每个数据页面必须实现：初始、加载、成功、有数据、空、部分失败、错误、无权限、已下架、离线/重试。Skeleton 只用于首次加载；后台刷新保留旧数据并显示轻量状态。

| 状态 | 表现 | 可执行动作 |
|---|---|---|
| 加载 | 与最终布局同形 Skeleton | 取消长任务 |
| 空 | 说明原因，不用纯“暂无数据” | 清除筛选/查看上一日/创建对象 |
| 部分失败 | 成功数据仍显示，失败区块就地提示 | 重试失败区块 |
| 错误 | 错误码、关联 ID、可恢复建议 | 重试/反馈 |
| 401 | 登录原因和返回地址 | 邀请登录 |
| 403 | 缺少的能力，不泄露对象存在性 | 返回公开区 |
| 410 | 内容已下架或删除 | 查看来源/提交反馈 |
| 429 | 剩余等待时间 | 到时重试 |

## 2. 状态机映射

- 收藏：未收藏 → 保存中 → 已收藏；失败回滚并提示。
- 订阅：草稿 → 启用 → 暂停/退订；退订后需明确重新订阅才能恢复。
- 长任务：QUEUED → RUNNING → SUCCEEDED/FAILED/CANCELLED；Agent 可进入 WAITING_APPROVAL。
- 审核按钮必须基于服务端当前版本；版本冲突提示刷新，不能覆盖他人修改。

## 3. 反馈约定

- 普通成功操作使用不打断 Toast，3～5 秒消失。
- 删除、下架、发布、批量重放、批准高风险工具必须使用确认对话框；危险按钮为红色且说明影响范围。
- 表单错误就地展示并在顶部给出摘要；焦点移动到第一个错误字段。
- 后台任务创建成功后立即显示任务 ID 与进度入口，而不是等待任务完成。

## 5. 核心组件

- `AppShell`：侧栏、移动抽屉、主题切换、登录/工作区入口。
- `PageHeader`：标题、副标题、最多三个主操作。
- `ContentCard`：compact/timeline/detail-preview 三种，不因来源类型改变骨架。
- `EventHotList`：排名、标题、独立信源数，行可点击。
- `StatusBadge`：OFFICIAL、UNCONFIRMED、DEBUNKED、精选、状态；颜色不是唯一信息。
- `FilterBar`：筛选写入 URL，可清空，可键盘操作。
- `CursorList`：加载更多，禁止无界自动滚动。
- `EvidenceCitation`：编号、标题、来源、时间、引用片段和权限状态。
- `JobProgress`：状态、步骤、耗时、Trace 和取消。
- `ConfirmDialog`：影响摘要、原因字段、确认文本和审计提示。
- `EmptyState`、`ErrorState`、`PermissionState` 统一组件。

## 6. 响应式规则

- ≥1200px：固定侧栏，多列主题，时间线卡片最大宽度随主区扩展。
- 768～1199px：侧栏收窄或抽屉；主题 2～3 列；筛选可换行。
- <768px：单栏；侧栏抽屉；时间移入卡片头；日报目录折叠；表格转字段列表；对话引用置于答案下方。
- 任何宽度均不得因长 URL、模型名、错误堆栈产生水平滚动；使用截断与展开。

## 7. 无障碍与键盘

语义化标题按层级；导航使用 `nav`；主内容有跳转链接；对话框焦点锁定并返回触发器；图标按钮有中文可访问名称；状态变化通过 `aria-live`；焦点轮廓清晰；正文和控件达到 WCAG AA 对比度；遵守 `prefers-reduced-motion`。

## 8. 原型验收清单

- 品牌名为 AI Hotspot，原 AI PULSE 文件保持不变。
- 无 X/微信公众号采集入口或文案。
- 左侧导航、时间线、内容卡、日报、主题和收藏视觉结构继承原型。
- 展示订阅邮件、事件详情、事实标记、权限边界和管理流程。
- 桌面与手机宽度可读，无控制台错误；至少验证一次导航和一次业务交互。
