# AI HOT 产品拆解

> 文档状态：草案  
> 参考地址：https://aihot.virxact.com/  
> 分析范围：公开可见的精选、全部动态、日报、主题、收藏、Agent 接入及内容详情结构。本文只分析可观察的产品行为，不推断其未公开的内部技术实现。

## 1. 产品定位判断

AI HOT 是一款面向 AI 从业者和关注者的高密度 AI 行业动态聚合与精选产品。它不是将抓取结果原样堆叠，而是对内容进行中文摘要、分类、评分、精选、推荐说明和热点归并，从而降低用户的信息筛选成本。

其核心用户承诺可以概括为：

> 用较短时间了解近期 AI 领域真正值得关注的变化，并保留返回站内详情和原始来源的路径。

## 2. 可观察的信息架构

### 2.1 主导航

公开主导航包括：

- 精选；
- 全部 AI 动态；
- AI 日报；
- 主题；
- 收藏；
- Agent 接入；
- 关于；
- 更新日志；
- 反馈。

这一结构将产品分为三类入口：

1. 内容消费：精选、全部、日报、主题、收藏；
2. 外部接入：Agent 接入；
3. 产品支持：关于、更新日志、反馈。

### 2.2 精选页

精选页承担首页和核心价值展示，主要结构为：

1. 日期与页面说明；
2. 分类切换：全部、模型、产品、行业、论文、技巧；
3. 当前热点：热点标题、排名、同时报道的信源数量；
4. 按日期和时间组织的内容时间线；
5. 搜索入口；
6. 浅色、深色和跟随系统主题。

### 2.3 内容卡片

公开页面中一条内容通常包含：

- 发布时间；
- 来源名称及来源类型；
- 精选标记；
- 质量或价值评分；
- 标题；
- 中文摘要；
- 可选配图；
- 分类和主题标签；
- 同事件其他信源提示；
- 推荐理由；
- 站内详情链接。

内容卡片将“事实摘要”和“编辑推荐理由”分开，这是值得保留的重要设计。摘要回答“内容说了什么”，推荐理由回答“为什么值得看、适合谁看、有什么局限”。

## 3. 关键产品机制

### 3.1 精选不是简单排序

页面同时展示“全部动态”和“精选”，说明完整采集池与精选结果在产品上有不同语义。精选应理解为经过质量、相关度、影响力和编辑判断后的结果，而不是只按时间或单一分数排序。

### 3.2 热点是事件而非文章

“多个信源同时报道”表明热点对象更接近事件。用户看到的热点标题不应简单等同于某篇文章标题，系统需要识别同一事实的不同报道，并统计独立信源。

### 3.3 分类与主题并存

- 分类用于快速消费，如模型、产品、行业、论文、技巧；
- 主题用于长期追踪，如公司、模型系列、Agent、多模态、部署工程。

AI Hotspot 需要避免把分类、标签、主题和实体混为一个字段。

### 3.4 来源信息是信任基础

页面明确标识官网、RSS、公众号、社区等来源形态。对于 AI 情报产品，来源等级、一手性和转载链识别必须进入数据模型，而不是只显示一个来源名称。

### 3.5 Agent 接入属于内容分发

AI HOT 的公开 Agent 接入页面主要提供 Agent Skill、RSS 和只读 REST API，使外部 Agent 能消费精选内容和日报。这与 AI Hotspot 规划中的内部 Research Agent、Subscription Agent 和运营 Agent 不是同一概念。

AI Hotspot 后续需要明确区分：

- **外部 Agent 接入**：向第三方提供只读内容能力；
- **站内 Agent 工作台**：在平台内部执行研究、订阅和运营任务。

## 4. 视觉与交互特征

- 固定窄侧边栏，内容区宽阔；
- 冷灰背景与白色卡片；
- 青绿色作为强调色；
- 字号克制、信息密度较高；
- 时间线使用竖线和时间节点；
- 圆角、边框和阴影较轻；
- 内容层级依靠间距、字号和颜色，而非大量装饰；
- 适合桌面端长时间阅读和快速扫描。

AI Hotspot 可以继承这种“高密度、低干扰”的设计方向，但需要形成自己的品牌、字体比例、组件系统和视觉细节。

## 5. 产品优势

1. 首页价值明确，用户无需学习即可开始浏览；
2. 摘要、标签和推荐理由降低判断成本；
3. 时间线适合高频资讯产品；
4. 热点与多信源提示增强事件感；
5. 日报和主题兼顾短期消费与长期追踪；
6. RSS、API 和 Agent Skill 提高内容分发能力；
7. 页面结构简单，核心内容始终占据视觉中心。

## 6. 对 AI Hotspot 的启发

AI Hotspot 应保留“资讯产品优先”的产品顺序：

```text
精选体验
→ 完整动态池
→ 事件热点
→ 日报与主题
→ 搜索与收藏
→ 研究、订阅和 Agent
```

不能一开始让 RAG 聊天框或管理后台掩盖内容产品本身。只有当采集、内容处理和事件数据可信时，RAG 与 Agent 才有实际价值。

## 7. 不可从公开页面得出的结论

公开页面无法证明以下事项，因此新方案不能照抄或假设：

- AI HOT 使用何种爬虫、消息队列或数据库；
- 热点评分和内容评分的具体算法；
- 公众号内容如何发现；
- 内容聚类是否完全自动；
- 是否保存全文、保存多久、是否用于私有索引；
- 编辑审核流程和内部权限；
- 模型供应商和 Prompt；
- 其内部运营成本和信源授权关系。

这些能力必须根据 AI Hotspot 自身目标重新设计。

## 8. 结论

AI HOT 最值得借鉴的是“产品呈现和信息编辑逻辑”，而不是不可见的技术实现。AI Hotspot 应以它为内容体验基准，在此基础上增加更透明的来源等级、跨事件关联、完整运营后台、可追溯 RAG、邮件订阅和受控 Agent。
