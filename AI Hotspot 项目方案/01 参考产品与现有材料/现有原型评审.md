# 现有原型评审

> 文档状态：草案  
> 评审对象：项目根目录 `AI_PULSE_PROTOTYPE.html`

## 1. 原型现状

现有原型是单文件 HTML/CSS/JavaScript 高保真演示，包含硬编码数据和模拟交互。它较完整地展示了旧方案设想的视觉方向和主要页面，但不是可直接延伸为正式应用的工程基础。

覆盖页面包括：

- 精选；
- 全部 AI 动态；
- AI 日报；
- 主题；
- 收藏；
- 内容详情；
- 知识库问答；
- Agent 工作台；
- 信源管理；
- 采集监控；
- 内容审核；
- 模型与 Prompt。

## 2. 值得保留的设计方向

### 2.1 整体视觉

- 冷灰背景、白色卡片、青绿色强调色；
- 左侧固定导航；
- 克制的圆角、边框和阴影；
- 内容信息密度较高；
- 支持浅色和深色主题；
- 桌面、平板和移动端有基础响应式适配。

### 2.2 内容卡片

卡片包含来源、渠道、精选标记、评分、标题、摘要、标签、推荐理由和收藏，基本符合 AI 情报产品的信息需求。

### 2.3 知识库三栏布局

桌面端将检索条件、对话和证据面板分开，有助于体现“基于筛选和证据回答”，比普通聊天页面更适合研究产品。

### 2.4 后台延续同一设计系统

管理端没有直接套用通用后台模板，而是与用户端共享色彩和组件语言，有利于品牌一致性。

## 3. 需要在现有原型上补齐的问题

### 3.1 用户端与管理端导航混杂

现有左侧导航、分组方式和整体布局继续保留。权限实现时，普通用户不显示信源管理、采集监控、内容审核和模型管理；具备权限的用户通过同一视觉系统进入管理工作区：

- 用户工作区导航；
- 研究与自动化入口；
- 具备权限后才能进入的管理工作区。

这属于权限和导航可见性调整，不代表重做整套界面。

### 3.2 缺少事件详情页

旧方案强调事件聚类，但原型没有真正的事件详情。新原型必须增加：

- 事件标题和事件摘要；
- 主条目；
- 关联内容；
- 来源角色和发布时间线；
- 独立信源数量；
- 事实、观点和传闻区分；
- 相关主题和实体；
- 基于该事件发起研究。

### 3.3 主题系统过于扁平

原型只展示 12 个主题卡片，缺少公司与模型、技术方向、内容形态等分组，也没有主题详情页、订阅和趋势解释。

### 3.4 搜索能力分散

精选和全部页面各有简单搜索框，但缺少统一搜索结果页。新原型应支持跨内容、事件、主题和实体搜索，并能选择时间、来源等级、语言和内容类型。

### 3.5 Agent 工作台表达不够完整

旧原型只有 Agent 卡片和运行列表，缺少：

- 创建任务表单；
- 运行计划；
- 步骤和工具调用；
- 等待审批；
- 审批参数；
- 中止和重试；
- 结果和引用；
- Token、费用和错误详情。

### 3.6 订阅与邮件缺少页面

原型出现“创建订阅”按钮，但没有订阅管理、自然语言解析预览、邮件样式和投递历史页面。

### 3.7 页面状态不足

多数页面只展示理想状态，缺少：

- 首次使用；
- 无数据；
- 加载和骨架屏；
- 请求失败；
- 部分数据失败；
- 无权限；
- 内容已下架；
- RAG 资料不足；
- Agent 等待审批；
- 邮件发送失败。

## 4. 工程层面的限制

- 所有数据硬编码在一个脚本中；
- 路由使用 Hash 模拟；
- 没有组件边界；
- 没有类型系统；
- 没有真实 API 和错误处理；
- 收藏仅保存在 LocalStorage；
- RAG 使用固定延迟和固定答案；
- Agent、采集、审批和模型管理均为 Toast 演示；
- 无认证、权限和可访问性验证；
- 示例资讯包含虚构内容，不能作为正式演示数据。

## 5. 新原型迭代方式

新原型以现有 `AI_PULSE_PROTOTYPE.html` 为界面和交互基线。原始文件不覆盖，派生出 AI Hotspot 新版本，并逐步映射到正式 Next.js 前端：

```text
现有页面结构、卡片和时间线
+ AI Hotspot 品牌替换
+ 已确认的页面与字段修订
+ 组件化设计系统
+ TypeScript 数据模型
+ Mock API 适配层
+ 完整交互状态
+ 响应式验证
```

页面先使用与正式 API 一致的 Mock 数据，后续替换数据来源时不重写组件。不得在实现过程中自行改变页面整体风格、布局密度或导航逻辑；确需结构性变化时先形成对比说明并由产品负责人确认。

## 7. 结论

旧原型是正式迭代起点，而不是准备丢弃的草图。后续工作是在其视觉和信息架构上补齐事件、搜索、订阅、审批、权限和异常状态，再逐步工程化为正式前端；不会进行未经确认的整体重设计。
