## 三、减少冗余的维护规则

1. **全局进度只写一处**：仅更新《项目进度与剩余任务》。
2. **全局架构只写一处**：仅更新《系统总体架构》，领域文档只描述局部设计。
3. **待办只写一处**：仅更新《后续任务清单》，验收记录只保存当时证据。
4. 标题含“评审”“任务拆分”“验收记录”“基线记录”的文档视为历史证据，不能覆盖现行文档。
5. 已执行的 Flyway 迁移不修改；数据库变化只能新增更高版本迁移，并同步字段中文说明。
6. 原型用于视觉与交互基线，真实代码、数据库和自动化测试决定当前实现状态。
7. 任何包含 API Key、密码、验证码或 Cookie 的内容不得写入方案、Git、日志和交接提示词。

## 四、冲突处理优先级

出现文档冲突时按以下优先级处理：

```text
用户最新明确指令
→ 已确认决策
→ 项目进度与剩余任务
→ 系统总体架构 / 数据库表全景 / RAG 详细设计
→ 产品与页面详细规格
→ 阶段验收记录和早期评审
```

不得为了迁就旧验收记录而回退已经确认的新规则。
