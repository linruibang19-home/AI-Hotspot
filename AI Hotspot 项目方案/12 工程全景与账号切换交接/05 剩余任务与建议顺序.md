# 剩余任务与建议顺序

> 本文是交接视图；唯一待办仍是 [后续任务清单](../11%20开发与交付计划/后续任务清单.md)。

## 1. 建议接手顺序

```text
先保稳定：OPS-DLQ-01 死信收敛
→ 再保 RAG：RAG-05 长尾延迟回归
→ 建证据：PERF-01 全栈压测基线
→ 做小步清理：CLEAN-01 无引用前端代码/产物
→ 做可维护性：ARCH-02 大文件拆分与 Docker 缓存
→ 有目标环境后：MAIL-01 / DATA-01 / OPS-01 / SEC-01 / LEGAL-01
```

## 2. 新增的内部任务

| ID | 优先级 | 任务 | 完成标准 |
|---|---|---|---|
| OPS-DLQ-01 | P1 | 收敛 9 条 PENDING 采集死信 | 定位每个 403 Endpoint；更正 URL/策略或归档不再可用来源；不删除审计记录；门禁 PASS |
| RAG-05 | P1 | 治理 7 天成功查询 P95 19.49s 长尾 | 固定样本/窗口/Provider；按阶段定位；连续回归 P95≤12s，质量和引用不回退 |
| PERF-01 | P1 | 全栈性能与容量基线 | 版本化压测脚本；完成公开读、搜索、RAG、Worker/DB/中间件指标；报告区分实测和目标 |
| CLEAN-01 | P2 | 删除高置信无引用 Web 文件 | 删除前后 `rg`；`pnpm check`；Compose Web 无头回归；不动 Mock Provider |
| ARCH-02 | P2 | 改善大文件与构建缓存 | 分批拆 `globals.css`、`repository.py`、RAG 治理类；AI Docker 依赖层可复用；行为不变 |
| CONTRACT-01 | P2 | 补齐 OpenAPI 与 Controller 契约 | 实际公开/管理 API 覆盖；增加 CI 漂移检查；不把 122 个信源 Endpoint 误写成 122 个 HTTP Endpoint |

## 3. 公开 Beta 前的外部任务

| ID | 任务 | 依赖的外部条件 |
|---|---|---|
| MAIL-01 | 真实 SMTP、SPF/DKIM/DMARC 和真邮箱验收 | 邮件服务商、发信域名 |
| DATA-01 | Linux 异机 PostgreSQL + MinIO 恢复 | 第二台主机/存储，RPO/RTO 目标 |
| OPS-01 | Linux + Nginx + HTTPS 持续运行 | 云主机、域名、证书 |
| SEC-01 | 密钥轮换、默认凭据禁用、SSRF/权限回归 | 新生产凭据，不得写入文档 |
| LEGAL-01 | 备案/许可评估、隐私、用户协议、版权/下架 | 上线地区、域名和运营主体 |

## 4. 持续项

- UI-01：只针对真实数据的桌面/移动问题做无头回归，关闭 Session；
- AGENT-01：取消、重试、审批过期、权限变化、断点恢复和长任务成本；
- 信源质量：来源配额、官方优先、事件去重、发布时间完整率；
- GIT-01：用户给出远程仓库授权后才配置 origin/CI/保护分支，未授权不 push。

## 5. 明确不做

- 不采集 X 和微信公众号；
- 不引入 LangGraph、Kafka、Elasticsearch、Kubernetes；
- 不允许 Mock/Test/Fixture 内容进公开池或 RAG；
- 不修改 V001～V031，数据库只新增 V032+；
- 不用可见浏览器做常规测试；
- 不在没有数据的情况下重写技术栈。
