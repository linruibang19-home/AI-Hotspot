## 2. 高置信可删代码候选

通过全仓 `rg` 引用检查，以下文件当前没有业务引入。建议在独立 `CLEAN-01` 提交中删除，并重跑 Web 全量检查：

- `apps/web/src/lib/mock-data.ts`：旧静态 Mock 数据，与“公开页面仅真实数据”方向不一致；
- `apps/web/src/components/content-card.tsx`：旧内容卡片，现行使用 `public-content-card.tsx`；
- `apps/web/src/components/workspace-page.tsx`：旧通用占位工作台，现行页面不引用；
- `apps/web/src/lib/topics.ts`：旧主题本地数据，无引用；
- `apps/web/public/file.svg`、`globe.svg`、`next.svg`、`vercel.svg`、`window.svg`：Next 初始模板图标，无引用。

删除前再执行 `rg` 和 `pnpm check`。如新代码在此期间重新引入，以实时引用图为准。

## 3. 可立即清理的本地产物

`artifacts/`、`.ruff_cache/`、`node_modules/`、`.next/`、`target/` 均不是源码。其中 `artifacts/web-runtime.tar` 约 736.6 MiB，是已忽略的构建产物；确认当前不需要用它回滚后可删除。

不建议本次自动删除，因为 `artifacts/` 中还有截图与验收证据；清理时应按明确文件执行，不对整个工作区做递归删除。

## 5. 不建议的“优化”

- 把三应用拆成大量微服务；
- 在当前 173 MB 数据库规模下引入 Elasticsearch 并承担双写；
- 为现有 RabbitMQ 工作量引入 Kafka；
- 在单机 Compose 还未做 Linux 验收时引入 Kubernetes；
- 为了流行而将可审计的 Agent 状态机改成 LangGraph；
- 重写前端 UI 或替换整个技术栈，而不是针对真实问题修复。
