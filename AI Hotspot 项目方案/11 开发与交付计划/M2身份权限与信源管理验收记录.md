## 2. 关键设计与安全结论

- 认证策略以《架构决策记录-003-认证会话策略》冻结，不采用浏览器 JWT；
- 浏览器只持有随机 Session ID，认证状态保存在 Redis；
- 修改请求必须同时具备有效会话与 CSRF Header；
- 邀请明文只在创建响应展示一次，数据库仅保存 SHA-256 Hash；
- ADMIN 可以管理用户与邀请；ADMIN/OPERATOR 通过 `source:*` Permission 管理信源；USER 被拒绝；
- SourceEndpoint 创建为 DRAFT，必须先获得 HEALTHY/WARNING 试抓取结果才能启用；
- `display_policy` 与 `index_policy` 分离，受限内容策略不会被公开展示策略隐式覆盖；
- X 与微信公众号没有 Connector、数据枚举、页面选项或采集接口；
- 所有信源写操作保存操作者、目标、前后数据、请求关联 ID 和客户端信息。
