## 1. 本次目标

在不改变既定产品信息架构和业务范围的前提下，将正式 Next.js Web 从工程骨架界面提升为可验收的完整产品界面。界面沿用原型中的左侧固定导航、冷灰背景、白色内容卡片、青绿色强调色、时间线信息流、报纸式报告和主题卡片体系。

## 2. 已完成页面

- 精选：分类、搜索、当前热点、日期分组、时间线、评分、精选理由和收藏；
- 全部 AI 动态：来源筛选、类型筛选、搜索、紧凑信息流和空状态；
- 内容详情：原始来源、内容策略、评分、标签、推荐理由和收藏；
- AI 日报：日报、周报、月报切换，归档栏、刊头、主线、指标、看点和分区文章；
- 主题：公司与模型、技术方向、内容形态三组主题卡片，并显示真实公开内容匹配数；
- 收藏：基于当前浏览器持久化的真实收藏与取消收藏；
- 登录后工作区：订阅与邮件、知识库问答、Agent 工作台；
- 辅助页面：关于、更新日志与反馈；
- 全局：语义化 SVG 图标、主题切换、响应式侧栏、桌面与移动布局。

## 3. 交互与真实性边界

- 筛选、搜索、报告周期切换、主题跳转和收藏交互可以使用；
- 精选、全部动态、内容详情、报告和主题读取现有真实 Core API 数据；
- 收藏当前保存在浏览器，跨设备收藏归入 M6 服务端闭环；
- 订阅、RAG、Agent 和反馈页面已完成产品界面，真实邮件投递、RAG 执行、Agent 长任务和反馈工单分别归入 M7～M9 或后续治理接口；
- 未伪造当前 API 不提供的事件信源数量、媒体附件或投递结果。

## 5. 本阶段结论

正式 Web 已覆盖原型定义的页面入口和主要视觉结构，可以作为 M6～M9 后端业务闭环的稳定展示层。这里的“完成”仅指前端页面与现有真实数据接口的展示范围，不代表订阅投递、RAG、Agent 等后续业务闭环已经完成。后续不得随意改换整体视觉框架；新增页面应复用本次形成的导航、变量、卡片、时间线、报告和工作台组件规范。

## 8. 第三轮逐页复核与纠偏

2026-07-18 产品负责人再次对照根目录正式原型后，确认此前实现仍存在“页面存在但入口不可见”和精选页结构偏移。本轮按 `AI_HOTSPOT_PROTOTYPE.html` 重新逐项核对，并完成以下纠偏：

- 侧栏不再按登录状态隐藏整组入口，固定展示原型中的“内容、智能、管理”三组；
- 未登录用户点击订阅、知识库、Agent 或管理入口时跳转登录页，并通过 `returnTo` 在登录后返回目标页面，不降低后端权限校验；
- 侧栏隐藏不属于当前正式原型主导航的“更多”组和“用户与邀请”入口，但保留对应业务路由；
- 精选页增加“导出日报”和“进入知识库”顶部操作；
- 精选筛选恢复为“全部、官方、论文、社区、媒体”，并直接基于真实信源元数据过滤；
- 热点榜恢复原型标题与说明结构，但不伪造 API 尚未提供的独立信源数量；
- 页面最大内容宽度恢复为原型的 `1540px`，卡片关键标题加粗，主题切换恢复原型的明暗双按钮；
- 修复 `390px` 下精选页两个顶部操作被截断的问题；
- Docker Web 镜像已重新构建，避免浏览器继续显示旧镜像中的旧筛选和旧侧栏。
