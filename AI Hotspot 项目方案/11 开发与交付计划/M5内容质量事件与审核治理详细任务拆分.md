# AI Hotspot M5 内容质量、事件与审核治理详细任务拆分

> 阶段状态：已于 2026-07-18 完成本地技术验收。  
> 实施分支：`feat/m5-content-quality-events`。

## 1. 阶段目标

M5 将 M3 的基础摘要与固定分升级为可运营的内容治理链：模型负责结构化理解，确定性规则负责硬约束，管理员负责高风险事实判断。内容必须能够追溯到模型运行、评分维度、重复主条目、一个或多个事件以及人工治理审计。

## 2. 数据与迁移

1. 使用 Flyway `V008` 增加分类、语言、置信度、质量维度、模型元数据、重复主条目和乐观锁版本；
2. 建立标签、实体、模型运行、事件聚类和内容事件多对多关系；
3. 建立纠错、下架、版权与审核工单；
4. 增加 `content:read`、`content:review`、`event:manage`、`ticket:manage` 权限；
5. 保持公开索引继续排除重复项和 `DEBUNKED`。

## 3. AI 结构化加工

1. Provider 输入明确禁止补充原文不存在的事实；
2. 输出包含中文标题、中文摘要、分类、标签、实体、事实状态、置信度和推荐理由；
3. JSON 解析失败时使用确定性规则降级，不能因为没有 API Key 阻塞启动；
4. 默认 Mock 可重复测试；配置 `openai-compatible` 时使用管理员提供的地址、模型和密钥；
5. 每次成功运行保存 Provider、模型、Prompt 版本、输入指纹和结构化输出；
6. `DEBUNKED` 只能由运营人工设置，模型最多自动标记 `UNCONFIRMED`。

## 4. 评分与准入

1. 相关度、完整性、清晰度、来源权威度和信息密度均限制在 0～100；
2. 最终分使用 `0.55 × relevance + 0.45 × quality`；
3. 默认阈值为相关度 70、质量 60，并继续由环境配置覆盖；
4. `UNCONFIRMED` 降权且禁止精选，低权威第三方未证实内容进入人工审核；`DEBUNKED` 禁止公开；
5. display policy、重复状态和事实状态作为评分后的硬规则执行。

## 5. 去重与事件

1. Canonical URL 相同视为精确重复；
2. 近 30 天标题 Jaccard 相似度不低于 0.88 视为近重复；
3. 重复项保存主条目和相似度，不得进入公开流；
4. 事件由分类、实体和标题特征生成稳定键；
5. 每条内容有一个受保护的主事件关系，并允许额外建立 `RELATED`、`FOLLOW_UP`、`CONTRADICTS` 关系；
6. 主事件关系不能通过普通删除接口移除。

## 6. 审核、反馈与审计

1. EDITOR 可读取审核队列，OPERATOR/ADMIN 可执行治理；
2. 支持批准、驳回、未证实、证伪、下架和恢复；
3. 每次治理必须填写理由并通过版本号防止并发覆盖；
4. 游客可提交纠错、下架和版权反馈；
5. 运营可解决或驳回工单；
6. 内容治理、跨事件关联和工单处理写入统一审计日志。

## 7. 界面

管理端 `/admin/content` 提供内容队列、事件聚类和反馈工单三个视图；展示管理专用的相关度、质量维度、重复主条目和事件关系。公开用户仍只看到最终分、来源与事实标记。

## 8. 完成定义

- Flyway V008 在现有数据上无损执行；
- Mock 和 OpenAI-compatible Provider 契约均可启动，缺少真实密钥时明确失败或使用默认 Mock；
- CONFIRMED、UNCONFIRMED、精确重复和跨事件关系均有集成证据；
- 下架、恢复、工单和 409 版本冲突均有接口证据；
- Python、Java、Web 全量检查和生产构建通过；
- Docker Compose 所有服务健康；
- 登录后管理页面完成桌面、移动端、交互和控制台验证。
