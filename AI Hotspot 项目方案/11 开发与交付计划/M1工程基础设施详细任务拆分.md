# AI Hotspot M1 工程与基础设施详细任务拆分

> 文档状态：待 M0 审核后执行；当前不编写业务代码。

## 1. M1 目标

建立可重复启动、可测试、可观测的工程骨架，使用 Mock Provider 跑通健康检查和空业务壳；不提前实现采集、内容、RAG 等完整业务。

## 2. 工作包

### M1-01 仓库结构

- `apps/web` Next.js 用户/管理端；`services/core` Spring Boot；`services/ai` FastAPI/Workers。
- `packages/contracts` OpenAPI/事件 Schema；`infra/compose`、`infra/nginx`；`scripts` PowerShell 包装。
- 根 README、贡献约定、编辑器配置、许可证与第三方声明占位。

验收：目录职责明确；构建命令不互相污染；无业务密钥入库。

### M1-02 Docker Compose

PostgreSQL+pgvector、Redis、RabbitMQ、MinIO、Mailpit、web/core/ai/worker；健康检查、命名卷、网络、资源限制和开发 profile。PowerShell 仅包装 `docker compose up/down/reset/logs`。

验收：Windows Docker Desktop+WSL2 一条命令启动；无远程 Key 时健康；重启数据保留；reset 明确确认。

### M1-03 配置与 Provider

分环境配置 Schema、`.env.example`、credentialRef；Generation/Embedding/Rerank/Mail Mock 与真实 Adapter 空壳；启动时检查但不打印密钥。

验收：Mock 默认可用；缺生产必需配置快速失败；日志脱敏。

### M1-04 数据库与消息基线

Flyway 引入、V001～V002；Outbox/Inbox 基础库；RabbitMQ exchange/queue/DLX 声明；correlation/trace 上下文。

验收：迁移从空库成功且可重复检查；消息重复消费用例通过。

### M1-05 API 与前端骨架

生成 OpenAPI 基线、Problem Details、认证占位、角色中间件；按冻结原型建立路由与 AppShell，数据使用 Mock API；加载/空/错误/权限状态组件。

验收：游客和受限路由行为正确；桌面/移动视觉基线通过。

### M1-06 质量与 CI

格式、lint、类型、单元、契约、迁移、Compose smoke、依赖/镜像/密钥扫描；主分支保护建议和 PR 模板。

验收：全新环境按 README 运行；CI 失败阻止合并；产物版本可追溯到 commit。

## 3. 建议执行顺序

`M1-01 → M1-02 → M1-03 → M1-04 → M1-05 → M1-06`。每个工作包独立 Issue/分支/提交；基础设施变更写 ADR。预计 1.5～2 周（单人全职参考），以验收完成而非日期作为完成标准。

## 4. M1 完成后剩余里程碑

M2 身份权限 → M3 信源采集 → M4 内容处理发布 → M5 事件主题搜索 → M6 RAG → M7 报告订阅邮件 → M8 Agent → M9 管理治理 → M10 Beta 硬化上线。
