- 导航和路由详细设计；
- 精选、全部、日报、主题、收藏逐页规格；
- 内容、事件、搜索、RAG、订阅和 Agent 页面规格；

- 页面加载、空、失败、无权限、下架和审批状态；

- 基线截图对照表。

### 3.2 业务领域

- 业务不变量和并发冲突规则。

### 3.3 数据与接口

- 分页、排序、错误、并发版本和权限；
- SSE 事件；
- MinIO 对象和签名访问；
- 邮件与退订接口。

### 3.4 AI 与安全

- Prompt 与模型路由；
- SSRF、Prompt Injection、密钥和上传安全；
- PUBLIC_RAG/PRIVATE_RAG 权限测试。

### 3.5 测试和运维

## 4. 迭代现有原型

方案详细到页面级后：

1. 从 Git 基线派生原型分支；
2. 保留原始 `AI_PULSE_PROTOTYPE.html`；
3. 创建 AI Hotspot 派生原型；
4. 先修订精选、全部、日报、主题、收藏；
5. 再补内容/事件/搜索；
6. 再补 RAG、订阅和 Agent；
7. 最后补管理端；
8. 进行桌面、平板和移动端对照检查；
9. 产品负责人审核；
10. 冻结 `prototype-v1`。

原型阶段仍不连接真实生产数据，也不编写完整后端业务。

## 5. 建立需求追踪和开发任务

- 给每项需求分配唯一编号；
- 建立需求 → 页面 → API/事件 → 数据表 → 测试 → 里程碑映射；
- 将 M1～M10 拆成可独立提交的任务；
- 为每个任务定义不修改范围；
- 为每个里程碑建立退出检查表。

## 6. 进入开发的必要条件

同时满足以下条件后，才开始 M1 工程：

- Git 基线已建立；
- 当前方案通过产品负责人审核；
- 页面详细规格完成；
- 正式原型通过审核；
- 核心领域状态机完成；
- 数据、API、异步、安全和测试方案达到可实施程度；
- 需求追踪矩阵和 M1 任务清单完成；
- 产品负责人明确批准开始开发。

## 7. 开发顺序

批准后严格按路线图执行：

```text
M1 工程和基础设施
→ M2 身份权限与信源
→ M3 RSS 垂直闭环
→ M4 公开 Connector
→ M5 内容质量与事件
→ M6 完整资讯产品
→ M7 RAG
→ M8 邮件订阅
→ M9 Agent
→ M10 验收与 Beta 准备
```

每个阶段审核通过后才进入下一阶段。
