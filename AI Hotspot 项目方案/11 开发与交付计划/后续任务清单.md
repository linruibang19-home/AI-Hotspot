## 1. 优先级说明

| 优先级 | 含义 |
|---|---|
| P0 | 影响运行正确性、数据安全或发布门禁，必须立即处理 |
| P1 | 公开 Beta 前必须完成 |
| P2 | 产品质量优化，可在稳定性之后迭代 |
| P3 | 有明确数据证明需要时再做，不预先增加架构复杂度 |

## 5. 每次任务的共同完成定义

一个任务只有同时满足以下条件才算完成：

1. 代码、迁移和配置在同一 Git 变更中；
2. Core、AI、Web 中受影响的自动化测试通过；
3. Docker Compose 中相关服务健康；
4. 用真实数据库和 HTTP 接口验证，不以静态 Mock 页面代替；
5. 数据与权限变化有审计，失败路径可观察；
6. 更新《项目进度与剩余任务》和本清单；
7. 说明已知限制，并形成可回滚的 Git 提交。

## 6. 不属于当前任务

- X 自动采集和微信公众号采集；
- Kubernetes、Kafka、Elasticsearch、多区域和大量微服务；
- 绕过 BYOK-01 所有权、烟测、配额或平台回落同意，向其他用户或前端暴露 Key；
- 即时推送；
- 在没有真实指标前重写现有技术栈。

历史 M1～M10 拆分和验收记录只用于追溯，不再继续追加“下一阶段”文字。
