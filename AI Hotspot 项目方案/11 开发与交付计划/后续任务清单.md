- 导航和路由详细设计；
- 精选、全部、日报、主题、收藏逐页规格；
- 内容、事件、搜索、RAG、订阅和 Agent 页面规格；
- 管理端逐页规格；
- 页面加载、空、失败、无权限、下架和审批状态；
- 视觉变量、组件和响应式规范；
- 基线截图对照表。

### 3.2 业务领域

- 用户和邀请状态机；
- SourceEndpoint 和 FetchJob 状态机；
- ContentItem 准入、发布、下架和恢复状态机；
- EventCluster 合并、拆分和跨事件关系；
- Subscription、EmailDelivery、AgentRun 和 Approval 状态机；
- 业务不变量和并发冲突规则。

### 3.3 数据与接口

- 数据库详细字段字典；
- 外键、唯一约束、索引和删除规则；
- Flyway 迁移顺序；
- 用户端、管理端、RAG 和 Agent API；
- 分页、排序、错误、并发版本和权限；
- SSE 事件；
- MinIO 对象和签名访问；
- 邮件与退订接口。

### 3.4 AI 与安全

- 内容处理 JSON Schema；
- 评分、去重和事件关联实验方案；
- Chunk、混合检索、Rerank 和 Citation Validator；
- Agent 工具与审批矩阵；
- Prompt 与模型路由；
- SSRF、Prompt Injection、密钥和上传安全；
- PUBLIC_RAG/PRIVATE_RAG 权限测试。

### 3.5 测试和运维

- 单元、集成、契约、E2E 和视觉回归；
- Connector Fixtures；
- RAG/Agent 评测集；

- 日志、指标和告警；
- 数据保留、备份和恢复；
- 性能和本地资源预算。

同时满足以下条件后，才开始 M1 工程：

- Git 基线已建立；
- 当前方案通过产品负责人审核；
- 页面详细规格完成；
- 正式原型通过审核；
- 核心领域状态机完成；
- 数据、API、异步、安全和测试方案达到可实施程度；
- 需求追踪矩阵和 M1 任务清单完成；
- 产品负责人明确批准开始开发。

## 7. 开发顺序

批准后严格按路线图执行：

```text
M1 工程和基础设施
→ M2 身份权限与信源
→ M3 RSS 垂直闭环
→ M4 公开 Connector
→ M5 内容质量与事件
→ M6 完整资讯产品
→ M7 RAG
→ M8 邮件订阅
→ M9 Agent
→ M10 验收与 Beta 准备
```

每个阶段审核通过后才进入下一阶段。
