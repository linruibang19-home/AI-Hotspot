# 架构决策记录 003：认证会话策略

> 状态：已接受
> 决策日期：2026-07-17
> 适用范围：MVP Web、Core API 与管理端

## 1. 背景

AI Hotspot MVP 面向公开访客和普通注册用户，当前没有第三方客户端、移动 App 或跨域开放 API。权限、账号停用和角色变更必须尽快生效，管理端写操作还必须具备 CSRF 防护和可撤销会话。

## 2. 决策

采用服务端安全 Cookie Session：

- Spring Security 负责认证和方法级授权；
- Spring Session 将不透明会话保存到 Redis，应用实例不保存本地会话状态；
- 浏览器只保存随机 Session ID，Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产启用 `Secure`；
- 写请求使用 Cookie CSRF Token 与 `X-XSRF-TOKEN` 请求头双重校验；
- 登录成功执行 Session Fixation 防护，退出登录立即删除服务端会话；
- 会话默认空闲有效期 12 小时，配置化管理；
- 密码登录、验证码发送/校验和可选邀请注册执行基于 Redis 的限流，管理员密码使用 BCrypt；
- 普通用户使用邮箱验证码注册和免密登录，数据库只保存带 pepper 的验证码摘要；
- 认证、登录失败、退出、公开注册、邀请使用、用户创建和角色变更进入审计或安全日志。

## 3. 未选择方案

- 短期 JWT + Refresh Token：当前没有跨域客户端需求，令牌撤销、角色即时生效和 Refresh Token 轮换会增加额外复杂度；
- 仅使用进程内 HttpSession：容器重启会丢失会话，也不支持未来多实例；
- 把访问令牌保存在 LocalStorage：扩大 XSS 后令牌泄露风险。

## 4. 边界与后续演进

- 游客公开浏览不创建会话；
- RAG、收藏、订阅、Agent 和管理端必须登录；
- ADMIN/OPERATOR 才能写信源，账号、邀请和角色只允许 ADMIN 管理；
- 若未来出现移动端、第三方客户端或公开写 API，再新增 ADR 评估 OAuth 2.1/OIDC 或短期访问令牌；
- 本决策关闭 NQ-001。
