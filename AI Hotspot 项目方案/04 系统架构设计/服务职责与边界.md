# AI Hotspot 服务职责与边界

> 文档状态：待确认

## 1. 边界原则

1. 认证、权限、发布、审批和审计由 Core API 最终裁决；
2. AI 输出是建议或处理中间结果，不直接绕过业务状态机；
3. 长任务通过 RabbitMQ，短查询通过 HTTP；
4. 一个业务事实只存在一个权威写入模块；
5. 服务间传递 ID、状态和结构化结果，不复制大文件；
6. 原始文件进入 MinIO，关系和索引元数据进入 PostgreSQL。

## 4. Python 模块

建议目录：

```text
services/ai-worker/app/
├── api/
├── connectors/
├── extraction/
├── processing/
├── deduplication/
├── clustering/
├── retrieval/
├── rag/
├── agents/

├── providers/
├── evaluation/
├── messaging/

```

Connector 只负责获取和标准化，不承担发布判断；Processing 只产生结构化结果，不直接决定用户权限；Provider 只封装模型调用，不携带页面业务逻辑。

## 5. 跨服务写入规则

- Worker 可以写入采集结果、处理结果、向量、模型运行和任务状态；
- 内容是否 PUBLISHED/PUBLIC 由 Core API 的准入和审核规则决定；
- Agent 写工具必须回到 Core API 执行，Agent Worker 不直接更新受保护业务表；
- 邮件 Worker 只发送已创建且状态允许的 EmailDelivery；
- 重放死信必须生成新的操作审计，并复用原 idempotencyKey 规则。

## 6. 权限过滤边界

Core API 在调用 AI API 前构建访问范围，包括：

- PUBLIC 内容；
- 当前用户拥有或被授权的 PRIVATE_RAG 数据集；
- 被下架、DEBUNKED 或不可索引内容排除条件。

AI API 必须把访问范围作为检索前置条件，不允许先召回私有内容再在生成后过滤。

## 7. 错误边界

- 业务校验错误同步返回统一错误结构；
- 可重试外部错误进入 RabbitMQ 延迟重试；
- 不可重试错误标记任务失败并记录原因；
- 超过最大次数进入 DLQ；
- Core API 提供失败详情和人工重放；
- 不允许捕获异常后静默成功。
