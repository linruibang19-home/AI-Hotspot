# AI Hotspot 技术选型说明

> 文档状态：已确认（具体依赖版本在工程初始化时锁定）

## 1. 选型总览

| 层级 | 技术 | 用途 |
|---|---|---|
| 前端 | Next.js、React、TypeScript | 用户端与管理端 |
| 样式组件 | Tailwind CSS、shadcn/ui | 设计系统基础，避免直接套模板 |
| 前端数据 | TanStack Query | 服务端状态、缓存和请求管理 |
| 流式交互 | Server-Sent Events | 普通 RAG 和运行状态增量展示 |
| 核心后端 | Java、Spring Boot | 业务、安全、权限、审批和审计 |
| 安全 | Spring Security、RBAC | 邀请制账号和角色权限 |
| 数据访问 | Spring Data JPA、MyBatis、受限 Spring JDBC | 聚合、SQL 密集业务与基础设施原语分层 |
| 迁移 | Flyway | 数据库版本管理 |
| API | OpenAPI | 契约和客户端生成基础 |
| AI API | Python、FastAPI、Pydantic | 同步 AI 与 RAG 接口 |
| Worker | Python、SQLAlchemy、RabbitMQ 客户端 | 采集和长任务 |
| Agent | LangGraph | 受控长流程编排 |
| 数据库 | PostgreSQL + pgvector | 业务、FTS 和向量 |
| 缓存 | Redis | 缓存、锁、限流、临时状态 |
| 消息队列 | RabbitMQ | 可靠任务、重试和死信 |
| 对象存储 | MinIO | 原始文件、快照和导出 |
| 邮件 | Mailpit / SMTP | 开发预览和真实发送 |
| 运行 | Docker Compose | 唯一标准运行方式 |
| 网关 | Nginx | Beta 反向代理、HTTPS 和静态策略 |

具体依赖版本在工程初始化时选择官方当前稳定或 LTS 版本，并通过 lockfile、构建文件和 ADR 固定，不在方案阶段写入可能快速过时的“最新版本号”。

## 2. 前端选型理由

- Next.js 支持公开资讯 SSR、路由和用户/管理端统一工程；
- TypeScript 约束复杂页面数据；
- Tailwind + shadcn/ui 提供可控基础，不直接复制通用后台外观；
- TanStack Query 适合筛选、分页、缓存、失效和后台状态；
- SSE 适合服务端到客户端单向流式回答，复杂度低于 WebSocket；
- UI 文案使用中文，代码使用 i18n Key，为未来国际化保留结构。

## 3. Spring Boot 选型理由

- 适合明确的事务、权限、审核、订阅和审计；
- Spring Security 提供成熟服务端授权；
- Spring AMQP 支持 RabbitMQ；
- Flyway 管理数据库迁移；
- Transactional Outbox 可与业务事务统一；
- OpenAPI 约束 Web 与后端契约。

### 数据访问边界

- Spring Data JPA 用于聚合根、简单查询、常规事务写入和后台 CRUD；
- MyBatis 是复杂筛选、全文/向量检索、报表、读模型及其他显式业务 SQL 的主框架；
- `NamedParameterJdbcTemplate` 仅保留给 Outbox/Inbox 领取、驱动级批处理和底层锁等基础设施原语；
- 三者共享 Spring DataSource、HikariCP 和事务管理，数据库结构只允许通过 Flyway 变更；
- Mapper 必须参数绑定、具有索引依据并由 PostgreSQL 集成测试验证。

## 4. Python 选型理由

- Connector、正文抽取、文本处理和 AI 库生态成熟；
- FastAPI/Pydantic 适合结构化 AI API；
- 同一代码库支持 API 和多个 Worker 启动模式；
- LangGraph 只用于需要状态、暂停、恢复和工具编排的 Agent，不用于普通确定性流水线。

## 5. 模型选型

### GenerationProvider

- 默认：DeepSeek OpenAI-compatible API；
- 低成本模型：摘要、分类、标签、翻译；
- 高质量模型：事件判断、复杂 RAG、研究报告；
- 具体模型名称通过管理员配置和任务路由决定。

### EmbeddingProvider

- 默认模型：BAAI/bge-m3；
- 支持本地服务或远程服务；
- 维度和模型版本随 KnowledgeChunk 保存。

### RerankProvider

- 默认模型：BAAI/bge-reranker-v2-m3；
- 支持本地或远程；
- 记录候选、分数、模型版本和延迟。

### Mock Provider

- MockGenerationProvider；
- MockEmbeddingProvider；
- MockRerankProvider。

Mock 必须确定性输出，仅用于启动、开发和自动化测试，不得伪装为真实 AI 结果发布。

## 6. PostgreSQL 与搜索

- PostgreSQL 保存完整核心数据；
- pgvector 保存 KnowledgeChunk 向量并支持去重/事件候选；
- PostgreSQL Full Text Search 是 MVP 关键词检索；
- 不使用 Elasticsearch/OpenSearch；
- 只有实际数据规模和查询压力证明需要时，才评估独立搜索服务。

## 7. RabbitMQ 与 Redis 边界

RabbitMQ：可靠异步、至少一次投递、重试、死信和 Worker 扩展。

Redis：缓存、锁、限流、热点和短状态。

禁止为减少一个容器而把核心任务重新放入 Redis。任何变更必须形成 ADR 并获得批准。

## 8. 不选择的技术

- Kafka：当前吞吐和团队复杂度不需要；
- Kubernetes：单机本地和单服务器 Beta 不需要；
- Elasticsearch/OpenSearch：PostgreSQL FTS + pgvector 足够验证 MVP；
- 本地大型生成模型：硬件成本和启动负担不符合当前环境；
- 多微服务：增加部署、契约和运维成本，当前模块化架构足够。

## 9. 配置和密钥

- 所有模型、SMTP、数据库、RabbitMQ、Redis 和 MinIO 配置来自环境或安全配置；
- `.env.example` 只包含示例键，不包含真实密钥；
- 模型 API Key 由管理员统一配置并加密；
- MVP 不支持用户自带 API Key；
- 日志不得输出 Authorization、Cookie、SMTP 密码或模型密钥。
