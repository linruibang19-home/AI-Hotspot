# AI Hotspot 技术选型说明

> 文档状态：现行；只记录代码中真实使用的技术。版本以锁文件、POM、PyProject 和 Compose 为准。

## 1. 实际技术栈

| 层级 | 当前技术 | 责任 |
|---|---|---|
| Web | Next.js 16、React 19、TypeScript、CSS | SSR/路由、用户端、智能端、管理端和响应式界面 |
| Core | Java 17、Spring Boot 4.1、Spring MVC/Security/Session | 业务、认证、权限、审计、RAG 编排与运维门禁 |
| 数据访问 | MyBatis + Spring JDBC；JPA 基础依赖 | SQL 密集查询、事务、基础设施原语；Flyway 管理 Schema |
| AI/Worker | Python 3.12、FastAPI、Pydantic、SQLAlchemy/psycopg、aio-pika | Connector、异步处理、Provider 适配与结构化 AI 输出 |
| 数据库 | PostgreSQL 16 + pgvector 0.8.5 | 关系数据、FTS、向量、审计和可靠消息记录 |
| 缓存/会话 | Redis 8 | Spring Session、限流、缓存和短期协调 |
| 消息 | RabbitMQ 4 | Outbox 后的异步任务、重试和死信 |
| 对象存储 | MinIO | 原始 RSS/HTML/JSON、快照和导出物 |
| 邮件 | Spring Mail + Mailpit/SMTP | 本地捕获与生产发送抽象 |
| 入口 | Nginx | 本地统一入口及未来 HTTPS 反向代理 |
| 运行 | Docker Compose | Windows 开发与单机 Linux Beta 的统一编排 |

Web 当前没有引入 shadcn/ui 或 TanStack Query 运行依赖；页面使用项目自己的组件和 CSS。未来只有在实际复杂度需要时才引入，不能把计划依赖写成已使用技术。

## 2. AI Provider

| 能力 | 默认真实配置 | 抽象 |
|---|---|---|
| 中文生成与内容分析 | DeepSeek OpenAI-compatible API | GenerationProvider |
| Embedding | SiliconFlow `BAAI/bge-m3` | EmbeddingProvider |
| Rerank | SiliconFlow `BAAI/bge-reranker-v2-m3` | RerankProvider |

三类 Provider 均由环境变量和数据库治理配置驱动，不硬编码密钥。Mock Provider 仅用于无 Key 的开发测试，数据库触发器禁止其内容进入公开产品和 RAG。

## 3. 数据访问决策

- Flyway 是唯一 Schema 变更入口；已执行迁移永不修改。
- MyBatis 承载公开流、主题、报告和其他需要明确 SQL 的查询。
- Spring JDBC 承载 Outbox、运维检查、批处理和 PostgreSQL 特性。
- JPA 依赖保留给适合聚合模型的场景，但当前不为简单 CRUD 强制增加 Repository 层。
- 同一事务共享 Spring 管理的 `DataSource`，禁止 Python 与 Java 同时争夺同一业务事实的最终写入权。

## 4. 为什么不增加更多组件

| 未采用 | 当前替代 | 原因 |
|---|---|---|
| Elasticsearch/OpenSearch | PostgreSQL FTS + pgvector | 当前数据量与检索需求足够，减少双写和运维 |
| Kafka | RabbitMQ | 任务队列、重试和死信更直接 |
| Kubernetes | Docker Compose | 单人、本地和单机 Beta 不需要集群复杂度 |
| LangGraph | 数据库状态机 + RabbitMQ Worker | 当前 Agent 流程尚不需要独立图运行时 |
| 本地大型生成模型 | 远程 DeepSeek | 降低硬件门槛 |
| 多套 Windows/Linux 脚本 | Compose + 少量 PowerShell 包装 | 避免两套部署路径漂移 |

## 5. 版本与升级原则

1. 依赖版本只从 `pnpm-lock.yaml`、`pom.xml`、`pyproject.toml` 和 `compose.yaml` 读取。
2. 升级先跑 Core、AI、Web 全量测试和生产构建，再重建 Compose。
3. PostgreSQL、RabbitMQ、Redis、MinIO 大版本升级必须先做备份恢复演练。
4. 重大技术替换新增 ADR，说明动机、替代方案、迁移和回滚。
5. 不因“主流”或“未来可能用到”引入尚无真实使用场景的框架。
