# 架构决策记录 002：AI 开发运行策略

> 状态：已接受
> 决策日期：2026-07-17
> 适用范围：Generation、Embedding、Rerank Provider

## 1. 背景

项目必须在 Windows + Docker Desktop + WSL2、16GB RAM 的最低建议环境上可启动。生成模型明确不在本地运行；bge-m3 与 bge-reranker-v2-m3 如强制随基础 Compose 本地启动，会显著增加首次下载、内存和启动时间，并让无 GPU 环境成为工程阻塞点。

## 2. 决策

- M1 默认配置统一使用 Mock Generation、Mock Embedding、Mock Rerank，不需要 API Key；
- 真实 Generation 默认接远程 DeepSeek OpenAI-compatible API；
- 真实 Embedding 与 Rerank 的开发默认采用可配置远程服务；
- bge-m3 和 bge-reranker-v2-m3 的本地运行作为可选 Profile，在 M7 进入真实检索评测前通过基准测试确定资源限制，不加入基础 Compose 默认启动链；
- 三类能力必须只通过 `GenerationProvider`、`EmbeddingProvider`、`RerankProvider` 接口调用；模型名、地址、密钥、超时和重试均来自环境配置；
- 非 Mock Provider 配置不完整时快速失败，日志不得输出密钥。

## 3. 原因

- 无远程密钥也能完成构建、单元测试和 Compose Smoke；
- 本地硬件不阻塞 M1～M6 的基础业务开发；
- 真实模型接入与业务代码解耦，可在 M4/M7 用固定评测集替换 Provider；
- 保留未来离线、本地推理或其他供应商的扩展能力。

## 4. 结果与约束

- NQ-003 关闭；
- M1 已实现三类接口及确定性 Mock Provider；
- 本地模型 Profile 未经资源与质量基准测试不得成为默认配置；
- 用户自带 API Key 仍不属于 MVP。
