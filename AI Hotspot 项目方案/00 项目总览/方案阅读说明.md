# AI Hotspot 项目方案阅读说明

## 1. 文档目的

本目录是 AI Hotspot 后续产品设计、原型设计、技术设计、开发、测试和验收的正式依据。

项目根目录下原有的 `AI_PULSE_DEVELOPMENT_SPEC.md` 与 `AI_PULSE_PROTOTYPE.html` 仅作为需求来源和历史参考，不再直接作为开发指令。新方案如与旧材料冲突，以本目录中最新且已确认的文档为准。

## 2. 当前阶段

第一轮“产品基线与信息架构”已经形成草案；当前新增了已确认的技术架构、RabbitMQ、数据模型、本地部署和里程碑方案，进入方案统一复核阶段。当前目标是：

1. AI Hotspot 是什么产品，核心价值是什么；
2. 主要服务哪些用户，解决哪些真实问题；
3. 与参考产品 AI HOT 的关系是什么；
4. 完整 MVP 包含什么、不包含什么；
5. 产品由哪些功能域和页面组成；
6. 关键用户如何完成核心任务；
7. 哪些问题已经确认，哪些问题必须后续决策。

当前阶段不开始工程代码开发。已由产品负责人确认的模型、RabbitMQ、Docker Compose、信源范围和部署决策已经进入正式方案；仍未确认的详细实现通过《待确认问题》和后续 ADR 管理。

## 3. 文档组织原则

- 文档目录和文件名称使用中文；
- 产品名称统一使用 **AI Hotspot**；
- 技术对象允许保留英文名，但首次出现时必须提供中文解释；
- 每份文档只解决一类问题，避免产品、技术和开发任务混在同一章节；
- 所有待定项进入《待确认问题》，不得用模糊文字跳过；
- 所有重大决定进入《已确认决策》，记录原因和影响；
- 后续需求必须能追踪到页面、业务规则、接口、数据表、测试和里程碑。

## 4. 文档状态

每份正式文档使用以下状态：

| 状态 | 含义 |
|---|---|
| 草案 | 已形成初步方案，仍需讨论 |
| 待确认 | 方案基本完整，等待产品决策 |
| 已确认 | 可作为后续设计和开发依据 |
| 已废弃 | 不再使用，但保留历史原因 |

本轮新建文档默认为“草案”。只有用户明确确认后才升级为“已确认”。

## 5. 版本与变更规则

- 方案采用 Git 进行版本管理后，每次重大方案变更单独提交；
- 不直接删除已经影响其他模块的决策，应先记录替代方案和迁移影响；
- 页面、接口、数据和测试之间出现冲突时，先修正文档再修改代码；
- 技术实现不得悄悄改变产品规则。
