# AI Hotspot 项目理解复核

> 文档状态：已更新（Q-001～Q-020 已确认并纳入；M0～M2 已完成本地技术验收）
> 本文对应原任务中提到的 `PROJECT_UNDERSTANDING_REVIEW.md`。根据项目“文档名称使用中文”的规则，正式文件命名为《项目理解复核》。

## 1. 当前产品理解

AI Hotspot 首先是一款面向个人和邀请制小范围用户的 AI 行业情报产品。它通过公开、可持续的 AI 技术信源，将分散内容加工为精选资讯、公开动态、热点事件、日报、主题和可检索知识，再在可信数据之上提供收藏、订阅、RAG 和 Research Agent。

产品不是 X 或微信公众号聚合器，也不是单纯爬虫、静态新闻站或通用聊天机器人。

## 2. 核心产品层次

```text
公开资讯体验
    精选 / 全部公开动态 / 热点 / 日报 / 主题 / 搜索 / 详情
        ↓
内容与事件基础
    信源 / 采集 / 提取 / 摘要 / 评分 / 去重 / 跨事件关联 / 审核
        ↓
登录用户能力
    收藏 / 每日与每周邮件 / RAG / Research Agent
        ↓
运营治理
    信源运营 / 采集监控 / 内容事件审核 / 报告 / 模型 Prompt / 审批审计
```

## 3. 用户和访问边界

- 游客：可访问精选、全部公开动态、日报、主题、公开内容详情和公开搜索；
- 邀请制用户：在游客能力上增加收藏、订阅、RAG 和 Agent；
- OPERATOR：可以新增和修改信源、处理采集和内容运营；
- ADMIN：拥有用户、权限、模型、Prompt、审批、审计和系统治理能力；
- 不开放公众自由注册，账号由管理员创建或通过邀请码注册；
- 未来公开注册只保留配置能力，不属于 MVP 当前行为。

## 4. 内容发布边界

“全部动态”不是原始采集池，只展示：

```text
SourceEndpoint 已启用
+ 内容提取成功
+ relevance_score >= 配置阈值（默认 70）
+ quality_score >= 配置阈值（默认 60）
+ 非重复主条目
+ display_policy 允许公开
+ 自动发布规则通过或人工审核通过
+ status = PUBLISHED
+ visibility = PUBLIC
```

原始池、候选池、重复内容、审核失败、私有内容和下架内容只在授权管理场景可见。

可信媒体的未证实报道可以标记 `UNCONFIRMED` 后进入全部动态，但降权且默认不进入精选；低可信传闻不公开；已证伪内容标记 `DEBUNKED` 并从默认结果移除。

## 5. 信源范围

MVP 主要使用 RSS/Atom、官方网站、Sitemap、GitHub、Hugging Face、arXiv、OpenReview、Hacker News、公开技术媒体和开发者社区。

明确不实现 X API、X 登录态或非公开接口、微信公众号扫码授权、自动订阅、登录态采集、WeChat Collector、WeRSS 或批量发现。人工复制相关 URL 也不作为核心能力。

## 6. 内容与索引策略

`display_policy`（展示策略）和 `index_policy`（索引策略）必须独立：

- 公开官网、公开技术博客、公开新闻、GitHub 和论文可按策略公开展示并进入 RAG；
- 付费墙、登录内容和明确受限内容不保存全文、不切片、不向量化；
- 只有管理员明确上传且确认拥有使用权限的材料可进入 PRIVATE_RAG；
- 权限过滤必须发生在全文和向量检索之前；
- RAG 和 Agent 不得引用当前用户无权访问的材料。

## 7. 正式技术架构

```text
浏览器
  ↓
Next.js Web（用户端 + 管理端）
  ↓
Spring Boot Core API
  ├── PostgreSQL + pgvector
  ├── Redis
  ├── RabbitMQ
  └── MinIO
          ↓
FastAPI AI API + Python Workers
          ↓
DeepSeek / bge-m3 / bge-reranker-v2-m3
```

- Spring Boot 管理确定性业务、认证授权、内容查询审核、订阅、报告、审计、Outbox 和 Agent 审批；
- Python 负责 Connector、正文处理、AI 内容加工、去重、事件、Embedding、Rerank、RAG 和 Agent 长任务；
- Redis 只承担缓存、锁、限流和短生命周期状态；
- RabbitMQ 是核心可靠异步任务队列；
- MinIO 保存原始 HTML/XML、快照、导出和授权上传文件；
- 普通 RAG 使用 HTTP + SSE；长时间 Agent 任务通过 RabbitMQ；
- 第一版采用模块化架构，不拆分大量微服务。

## 8. AI 模型边界

- 生成模型：远程 DeepSeek OpenAI-compatible API；
- Embedding：BAAI/bge-m3；
- Rerank：BAAI/bge-reranker-v2-m3；
- 通过 GenerationProvider、EmbeddingProvider、RerankProvider 抽象；
- 模型名称、地址、密钥、超时、重试和任务映射配置化；
- 提供三类 Mock Provider；
- 本地不运行大型生成模型；
- MVP 不支持用户自带 API Key。

## 9. 可靠异步处理

RabbitMQ 使用 Topic Exchange `aihot.events`，承担采集、内容处理、Embedding、事件聚类、报告、邮件和 Agent 长任务。

可靠性机制包括：

- Durable Exchange/Queue；
- Persistent Message；
- Publisher Confirm；
- Manual ACK 与 Prefetch；
- 指数退避重试；
- Dead Letter Exchange/Queue；
- Transactional Outbox；
- Consumer Inbox；
- eventId、idempotencyKey、correlationId 和 traceId；
- 管理端失败任务查看和人工重放。

## 10. 本地与 Beta 部署

开发环境统一为 Windows 10/11 + Docker Desktop + WSL2 + Docker Compose。PowerShell 只封装 Compose 操作。最低建议为 4 核 CPU、16GB RAM 和 40GB 可用空间。

MVP 后的邀请制 Beta 使用单台 Linux 云服务器、Docker Compose、Nginx、HTTPS、PostgreSQL/pgvector、Redis、RabbitMQ 和 MinIO。第一版不使用 Kubernetes、Kafka、Elasticsearch/OpenSearch、多节点数据库或多区域部署。

## 11. MVP 完成含义

MVP 完成不是所有页面出现，而是以下闭环真实运行：

1. 邀请制账号和游客边界有效；
2. 真实公开信源被采集并保存原始证据；
3. 内容通过 AI 处理、准入、审核和发布；
4. 内容可形成事件并支持跨事件关联；
5. 用户可浏览、搜索、收藏和查看日报；
6. 登录用户可执行权限安全的 RAG；
7. 每日和每周邮件可发送、退订和重试；
8. Research Agent 可完成带引用任务；
9. 管理员可查看失败、死信、审批和审计；
10. 整体可通过 Docker Compose 本地启动并验证。

## 12. 当前结论

项目的核心已经收敛为：

> 以公开、合规、可持续信源构建高质量 AI 资讯产品；以事件和证据建立可追溯知识层；以权限安全的 RAG、邮件和 Agent 提供个人化研究与自动化能力。
