## 8. 正式技术架构决策

### DEC-008：模块化三端架构

- Next.js 用户端和管理员端；
- Spring Boot 核心业务服务；
- FastAPI AI API 与 Python 异步 Worker；
- PostgreSQL + pgvector；
- Redis；
- RabbitMQ；
- MinIO；
- Mailpit/SMTP；
- Docker Compose；
- Nginx。

第一版不拆分大量微服务。

### DEC-009：RabbitMQ 是正式可靠消息队列

- RabbitMQ 负责采集、内容处理、Embedding、聚类、报告、邮件、Agent 长任务、重试和死信；
- 使用 Durable Exchange/Queue、Persistent Message、Publisher Confirm、Manual ACK、Prefetch、DLX/DLQ；
- 使用 Transactional Outbox 解决数据库提交与消息发布一致性；
- 使用 Consumer Inbox 实现消费者幂等；
- Redis 不承担核心可靠异步任务，禁止用 Redis List 或 Redis Streams 替代 RabbitMQ，除非后续形成并批准新 ADR。

### DEC-010：暂不使用的基础设施

- Kubernetes；
- Kafka；
- Elasticsearch/OpenSearch 集群；
- 多节点数据库；
- 多区域部署；
- 大量独立微服务。

“不使用 Kafka”不等于“不使用消息队列”，MVP 明确使用 RabbitMQ。

## 9. 原型与版本管理决策

### DEC-011：现有原型是后续界面迭代基线

- `AI_PULSE_PROTOTYPE.html` 和产品负责人提供的 AI HOT 页面截图是界面参考基线；
- 后续原型必须在现有原型的信息密度、左侧导航、时间线、卡片、日报、主题和收藏风格上迭代；
- 只根据已确认的 AI Hotspot 产品方案增删页面、字段、状态和权限，不进行未经确认的整体改版；
- 新增事件、RAG、订阅、Agent 和管理页面时继续使用同一视觉语言；
- 原始 HTML 文件保留为历史参考，新迭代从其派生，不覆盖或丢失基线；
- 关键页面修改后必须进行桌面对照和响应式视觉检查。

### DEC-012：项目必须使用 Git 管理

- 在任何原型或业务代码修改前初始化项目根目录 Git 仓库；
- 首次基线提交包含原始参考文件和当前已确认方案；
- 原始参考文件在基线提交后保持可追溯；
- 后续使用任务分支和小步提交，不把多个无关功能混在一个提交；
- `.env`、密钥、数据库卷、MinIO 数据、日志、模型缓存和构建产物不得提交；
- 每个里程碑使用 Git Tag；
- 未经用户授权不向远程仓库推送、不创建公开仓库；
- 禁止使用破坏性重置覆盖用户改动。

## 10. M1 补充架构决策

### DEC-013：Java 数据访问采用 JPA + MyBatis + 受限 JDBC 分工

- Spring Data JPA 负责聚合根、简单查询和常规事务写入；
- MyBatis 负责复杂筛选、管理端查询、FTS、pgvector、报表、读模型和 SQL 密集业务；
- `NamedParameterJdbcTemplate` 仅负责 Outbox/Inbox 领取、驱动级批处理和底层锁等基础设施原语；
- Flyway 是唯一 Schema 变更入口，Hibernate 只执行 `validate`；
- 三种访问方式共享 Spring DataSource 和事务边界，不得在单个 Repository 中无边界混用。详细理由见《架构决策记录 001：Java 数据访问策略》。

### DEC-014：AI 开发默认 Mock，真实模型默认远程

- 基础 Compose 默认使用三类确定性 Mock Provider；
- 真实生成模型使用远程 DeepSeek OpenAI-compatible API；
- 真实 Embedding/Rerank 的开发默认使用可配置远程服务；
- bge-m3 与 bge-reranker-v2-m3 的本地运行保留为后续可选 Profile，不进入 M1 默认启动链。详细理由见《架构决策记录 002：AI 开发运行策略》。

## 11. M2 补充架构决策

### DEC-015：认证采用 Redis 服务端安全 Cookie Session

- Spring Security 负责认证、RBAC 和方法级权限；
- Spring Session 将不透明会话保存到 Redis；
- Session Cookie 使用 HttpOnly、SameSite=Lax，生产环境启用 Secure；
- 写请求强制 CSRF Token，登录和邀请注册执行 Redis 限流；
- 登录成功迁移 Session ID，退出立即撤销会话；
- 当前不采用 JWT + Refresh Token；未来出现移动端或第三方客户端时重新评估。详细理由见《架构决策记录 003：认证会话策略》。
