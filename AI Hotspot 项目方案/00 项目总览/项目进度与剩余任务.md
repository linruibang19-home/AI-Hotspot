# AI Hotspot 项目进度与剩余任务

> 更新时间：2026-07-22；这是全项目当前状态的唯一事实来源。瞬时数据以本轮 PostgreSQL、Docker Compose、自动化测试和发布门禁为准。

## 1. 总体结论

M0～M10 已完成本地产品闭环，当前阶段是“稳定性、信源质量、RAG 质量与公开 Beta 准备”，不是重新搭建框架。产品已有公开资讯、主题时间线、日报/周报/月报、邮箱注册登录、收藏订阅、RAG 研究、受控 Agent 和管理治理。DeepSeek Generation、SiliconFlow `BAAI/bge-m3` Embedding 与 `BAAI/bge-reranker-v2-m3` Rerank 已接入真实服务；公开产品与 RAG 中 Mock 内容为 0。

本地闭环不等同于互联网公开 Beta。生产 SMTP、Linux/Nginx/HTTPS、异机恢复、域名备案和内容合规仍需目标环境验收。

## 2. 当前实际架构

- 代码应用：`apps/web`、`services/core`、`services/ai`，共 3 个；
- Compose 服务：Web、Core API、AI API、Worker、PostgreSQL+pgvector、Redis、RabbitMQ、MinIO、Mailpit、Nginx，共 10 个；
- PostgreSQL：单实例、8 个业务 Schema、55 张业务表；
- Worker：一个 Python Worker 消费采集、内容分析、索引等多类队列；
- 运行标准：Docker Compose；PowerShell 仅包装启动、停止、测试和运维；
- 当前不需要 LangGraph。只有当 Agent 出现持久化图状态、复杂循环/并行分支且现有状态机无法维护时才重新评估。

## 5. 本轮架构和稳定性整改

1. 建立 `AI Hotspot 项目方案/README.md` 作为唯一方案入口，明确进度、架构、数据库和待办各自只有一个现行文档。
2. 总体架构收敛为 3 个代码应用和 10 个 Compose 服务，删除“每类任务一个 Worker 服务”等与实际代码不符的描述。
3. 技术选型只保留实际依赖，移除尚未使用的 shadcn、TanStack 等已实现表述；继续采用 Spring JDBC/MyBatis 风格的显式 SQL边界，Flyway 是唯一 DDL 入口。
4. V024 修复保留任务查询不存在的 `iam.email_verification_code`，统一使用真实表 `iam.email_verification_challenge`，避免整批维护事务回滚。
5. Connector 的关键词过滤允许健康的 0 条匹配结果，不再把“Feed 可访问但没有 AI 内容”误记为采集失败；少数派端点已恢复健康。
6. V024 与维护服务把端点后来成功或已归档的历史死信标为 `IGNORED`，保留审计但不阻塞发布门禁；当前 PENDING=0。
7. 可见浏览器自动化不作为常规检查手段；需要 UI 回归时必须使用项目无头配置并关闭 Session，避免弹窗闪烁影响电脑使用。
8. V025 建立 7 天实时信源质量视图与周度快照，按质量、公开转化、非重复和原始发布时间完整率评估 Endpoint；来源份额作为多样性护栏。自动治理只对样本充分且连续多周低质的第三方来源生效，官方/一手来源仅告警。首轮 82 个现行非测试 Endpoint 中，24 个健康、10 个观察、7 个低质、41 个样本不足，尚未触发自动降权或暂停。

## 6. 当前产品边界

- 游客可浏览公开精选、全部动态、报告、主题、内容详情和公开搜索；
- 普通用户开放邮箱验证码注册与登录，收藏、订阅、RAG 与 Agent 登录后使用；
- 管理端只允许 ADMIN/OPERATOR；引导管理员账号由本机 `.env` 创建；
- X 与微信公众号不采集，X 只保留禁用的扩展契约；
- 不支持用户自带模型 Key；密钥仅存本机 `.env`；
- 不使用 Kubernetes、Kafka 或 Elasticsearch。
