# AI Hotspot 项目进度与剩余任务

> 更新时间：2026-07-23；这是全项目当前状态的唯一事实来源。瞬时数据以本轮 PostgreSQL、Docker Compose、自动化测试和发布门禁为准。

## 1. 总体结论

M0～M10 已完成本地产品闭环，当前阶段是“稳定性、信源质量、RAG 质量与公开 Beta 准备”，不是重新搭建框架。产品已有公开资讯、主题时间线、日报/周报/月报、邮箱注册登录、收藏订阅、RAG 研究、受控 Agent 和管理治理。DeepSeek Generation、SiliconFlow `BAAI/bge-m3` Embedding 与 `BAAI/bge-reranker-v2-m3` Rerank 已接入真实服务；公开产品与 RAG 中 Mock 内容为 0。

本地闭环不等同于互联网公开 Beta。生产 SMTP、Linux/Nginx/HTTPS、异机恢复、域名备案和内容合规仍需目标环境验收。

## 2. 当前实际架构

- 代码应用：`apps/web`、`services/core`、`services/ai`，共 3 个；
- Compose 服务：Web、Core API、AI API、Worker、PostgreSQL+pgvector、Redis、RabbitMQ、MinIO、Mailpit、Nginx，共 10 个；
- PostgreSQL：单实例、8 个业务 Schema、56 张业务表；
- Worker：一个 Python Worker 消费采集、内容分析、索引等多类队列；
- 运行标准：Docker Compose；PowerShell 仅包装启动、停止、测试和运维；
- 当前不需要 LangGraph。只有当 Agent 出现持久化图状态、复杂循环/并行分支且现有状态机无法维护时才重新评估。

本次交接于 2026-07-23 重跑 Web 18 项测试与生产构建、Core 35 项测试、AI 36 项测试、Compose 配置以及 M7～M10 Beta Readiness，全部 PASS。Readiness 通过表示当前未触发硬门禁，不会消除 9 条死信和 RAG 长尾这两个已识别的优化任务。

最近 72 小时公开量仍有信源集中：IT之家 150、arXiv 95、阿里云通义 48、GitHub Copilot 25；精选接口已有单信源上限，但“全部动态”和 RAG 仍需要通过来源配额、官方优先和事件去重继续改善多样性。数字会随 Worker 运行增长。

最新 RAG 黄金集含 50 个用例，覆盖主题检索、官方限定、7/30/90 天时间窗口、中英混合、多信源/多跳、冲突问题、无证据和 ACL 边界。2026-07-22 真实 Provider 回归 Recall@20=1.0、nDCG@10=0.974、引用支持率=1.0、ACL 泄漏=0，50 条约束全部通过。RAG-02 的 12 条真实问题批测平均 7.683 秒、P95/最大值 8.835 秒；检索均值 1.720 秒、生成均值 5.804 秒，达到本地 P95≤12 秒目标。

RAG-04 完成后最近 20 次真实成功查询平均 10.050 秒、P95 11.970 秒、最大 16.708 秒，短窗口仍满足本地 P95≤12 秒。但 2026-07-23 重算的近 7 天 86 次成功查询平均 10.237 秒、P95 19.490 秒，说明长尾尚未持续达标，已转为 RAG-05 待办。当前管理端可切换 24/72/168 小时，展示阶段均值/P95、小时趋势、Provider 错误率和 Token、无证据原因、慢查询、证据与索引护栏，并按 PASS/FAIL 筛选评测历史。

SRC-02 完成后，V030 为 Raw Entry、Content 与 Chunk 保存来源发布时间的解析依据，并增加按 Endpoint 的完整率、来源覆盖率和未来时间监控视图。公开内容缺原始来源时间从 143 降至 100（下降 30.1%），其中 RSS 从 8 降至 0、WEBSITE 从 135 降至 100；缺时间 Chunk 从 172 降至 104。所有已有日期的公开内容解析来源覆盖率为 100%，未来时间仍为 0。未出现标题或 URL 显式日期的内容继续保留为空，不用抓取时间冒充原始发布时间。

SRC-03 完成后，V031 将单次轮询明确分为发现新内容、正常零新增、HTTP 304、上游失败、内容结构失败和取消，并在 Endpoint 保存最近结果及连续无变化次数。迁移后的 7 天真实任务为 9,206 次：523 次发现新增、8,568 次健康无变化、93 次上游失败、22 次内容失败；健康无变化结果关联死信为 0。重建后的实际轮询已同时验证 `NEW_CONTENT`、`NO_NEW_CONTENT` 和 `NOT_MODIFIED` 均按预期落库，管理端不再把零新增显示为失败。精选与全部动态的日期组可折叠，桌面时间字号由 10px 提升为 14px，移动端由隐藏改为 12px 可见。

日期折叠复核发现，数据库并非只有一天：7 月 22 日、21 日和 20 日分别有 110、123、204 条公开内容；原问题是 `/all` 每次只取 20 条，前 40 条仍被同一天占满。现已保持游标连续读取并在首屏至少覆盖两个日期，不跳过中间资讯；折叠箭头改为固定 22px 圆形 SVG，桌面和 390px 移动端标题/圆心/图标垂直中心偏差均为 0px。

## 5. 本轮架构和稳定性整改

1. 建立 `AI Hotspot 项目方案/README.md` 作为唯一方案入口，明确进度、架构、数据库和待办各自只有一个现行文档。
2. 总体架构收敛为 3 个代码应用和 10 个 Compose 服务，删除“每类任务一个 Worker 服务”等与实际代码不符的描述。
3. 技术选型只保留实际依赖，移除尚未使用的 shadcn、TanStack 等已实现表述；继续采用 Spring JDBC/MyBatis 风格的显式 SQL边界，Flyway 是唯一 DDL 入口。
4. V024 修复保留任务查询不存在的 `iam.email_verification_code`，统一使用真实表 `iam.email_verification_challenge`，避免整批维护事务回滚。
5. Connector 的关键词过滤允许健康的 0 条匹配结果，不再把“Feed 可访问但没有 AI 内容”误记为采集失败；少数派端点已恢复健康。
6. V024 与维护服务把端点后来成功或已归档的历史死信标为 `IGNORED`，保留审计但不阻塞发布门禁；当前 9 条 PENDING 主要来自上游 Release Feed HTTP 403，不删除审计记录，等待后续成功后自动收敛。
7. 可见浏览器自动化不作为常规检查手段；需要 UI 回归时必须使用项目无头配置并关闭 Session，避免弹窗闪烁影响电脑使用。
8. V025 建立 7 天实时信源质量视图与周度快照，按质量、公开转化、非重复和原始发布时间完整率评估 Endpoint；来源份额作为多样性护栏。自动治理只对样本充分且连续多周低质的第三方来源生效，官方/一手来源仅告警。首轮 82 个现行非测试 Endpoint 中，24 个健康、10 个观察、7 个低质、41 个样本不足，尚未触发自动降权或暂停。
9. 本地 Web 已重新构建为最新 Docker 镜像，`web` 与 `nginx` 由 Compose 统一管理，`http://127.0.0.1:8088` 是标准入口；本机不常驻 `next dev`。`.dockerignore` 排除 4.5GB 本地验收产物后，Web 构建上下文从近 1GB 的无效传输降至约 1.45MB。
10. V026～V028 将 `RAG_BASELINE_ZH` 从 10 条扩展到 50 条并升级为 3.1；评测器按用例执行时间、官方、来源类型过滤，检查关键词命中、来源多样性、公开 ACL 边界和预期无证据，不再只按单一关键词判断。门禁阈值提升为 Recall@20≥0.85、nDCG@10≥0.80、引用支持率≥0.95、最少 50 条。
11. RAG 查询诊断增加查询理解、权限/会话、Embedding、混合召回、Rerank、去重、生成、引用校验/兜底、持久化和总耗时；召回规模收敛为 64/64 候选、32 条重排、8 条上下文，模型输入截断到每段 900 字。引用覆盖不足或编号越界时改为确定性证据摘录，不再进行第二次模型修复，避免额外网络耗时且保证引用可落库。
12. `/research` 重构为连续研究画布：六阶段实时进度、主答案阅读区、轻量筛选栏、证据栏、正文引用联动、加载/渐入动效与 reduced-motion 支持；Compose 桌面和 390px 手机无头回归通过。
13. V029 将“引用质量”与“证据语义”拆开：`research.citation.support_status` 继续表示引用片段是否充分，`research.evidence_assessment` 独立记录同一主张的支持、反驳、未证实，以及当前、过期、未知时效。模型给出初判，服务端以内容治理状态和时间窗口做确定性覆盖；同一主张同时出现支持和反驳时，回答与工作台明确提示冲突，不把单一来源写成事实。
14. RAG-04 复用 `query_run.retrieval_diagnostics`、`provider_metric` 和 `evaluation_run`：新查询写入结构化无证据原因，远端 Generation 返回的实际 Token 与失败降级进入 Provider 指标；管理 API 支持时间窗口和评测结果筛选，慢查询按 12 秒阈值优先展示。`/admin/models` 已重构为状态摘要、阶段/趋势、Provider/证据护栏、慢查询、评测历史和配置六层工作台。
15. V030 为 RSS/ATOM、网页、GitHub、Hugging Face、OpenReview、Hacker News 与 Sitemap 统一保留发布时间解析来源；网页标题支持英文长/短月份、ISO/中文日期，网页和缺日期 Feed 支持显式 URL 日期。历史回填只接受 1990 年以后且不晚于当前时间的明确日期，并同步 Raw、Content、Chunk 与有效时间。
16. V031 建立 Connector 轮询业务结果模型与 7 天健康视图；成功但零新增、HTTP 304 与失败彻底分离，上游网络/拒绝和内容结构错误分别统计。采集监控展示业务结果和正常零新增数量，避免用“无新增”制造假告警或死信。
17. 精选和全部动态的首屏加载由固定条数改为“至少两个日期组、最多五页”的连续游标读取；日期组保持完整排序并可折叠，圆形 SVG 箭头替换字体字符，解决只有一天标题和箭头基线偏移问题。

## 6. 当前产品边界

- 游客可浏览公开精选、全部动态、报告、主题、内容详情和公开搜索；
- 普通用户开放邮箱验证码注册与登录，收藏、订阅、RAG 与 Agent 登录后使用；
- 管理端只允许 ADMIN/OPERATOR；引导管理员账号由本机 `.env` 创建；
- X 与微信公众号不采集，X 只保留禁用的扩展契约；
- 不支持用户自带模型 Key；密钥仅存本机 `.env`；
- 不使用 Kubernetes、Kafka 或 Elasticsearch。
