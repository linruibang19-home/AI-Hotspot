# AI Hotspot 项目术语表

> 文档状态：草案

## 1. 产品与内容术语

| 中文术语 | 英文/代码名称 | 定义 |
|---|---|---|
| 信源主体 | SourceEntity | 产生内容的组织、公司、研究机构、媒体、社区或作者，例如 OpenAI、Anthropic、机器之心 |
| 信源入口 | SourceEndpoint | 信源主体下可被采集的具体入口，例如官网新闻、RSS、Sitemap、GitHub Releases 或论文 Feed |
| 连接器 | Connector | 负责校验、获取和标准化某类信源入口的统一采集组件 |
| 采集任务 | FetchJob | 针对一个信源入口执行的一次采集行为及其状态记录 |
| 采集原件 | FetchArtifact | 一次 HTTP、RSS、API 或文件响应的原始保存对象 |
| 原始条目 | RawEntry | 从采集原件中拆出的单篇候选文章、Release、论文或帖子 |
| 内容条目 | ContentItem | 经规范化、正文抽取和基础处理后可进入产品的数据对象 |
| 精选内容 | FeaturedContent | 经规则、AI 或人工判断后进入精选信息流的内容条目 |
| 事件 | EventCluster | 现实中发生的一件事实或变化，例如某模型发布、某产品更新、某次融资 |
| 内容事件关联 | ContentEventRelation | 内容与事件之间的多对多关系，包含角色、置信度、原因和审核状态 |
| 主条目 | PrimaryContent | 在一个事件中最适合作为核心事实来源的内容，优先选择官方公告、论文或 Release |
| 主题 | Topic | 跨事件、跨时间持续存在的关注方向，例如 Agent、AI 编码、多模态 |
| 实体 | Entity | 公司、模型、产品、人物、组织、技术或项目等可识别对象 |
| 标签 | Tag | 对内容进行快速描述和筛选的轻量分类标记 |
| 热点 | HotTopic | 在短时间内由多个独立信源共同报道、具有较高影响或关注度的事件 |
| 推荐理由 | RecommendationReason | 解释内容为什么值得阅读、适合哪些用户以及价值在哪里的编辑性说明 |

## 2. 知识与研究术语

| 中文术语 | 英文/代码名称 | 定义 |
|---|---|---|
| 知识切片 | KnowledgeChunk | 从标题、摘要或正文中切分出的最小可检索证据单元 |
| 混合检索 | HybridSearch | 将元数据过滤、全文搜索和向量检索结合的召回方式 |
| 重排序 | Rerank | 对初步召回结果进行更精确的相关性排序 |
| 检索增强生成 | RAG | 基于实际检索证据生成回答的流程 |
| 证据 | Evidence | 支持某项结论的具体内容切片和来源信息 |
| 引用 | Citation | 回答或报告中指向证据、站内详情和原始来源的结构化对象 |
| 引用验证 | CitationValidation | 检查引用是否存在、是否满足过滤条件、是否支持相邻结论的过程 |
| 研究任务 | Research | 围绕一个问题执行检索、比较、时间线整理和报告生成的任务 |

## 3. Agent 与治理术语

| 中文术语 | 英文/代码名称 | 定义 |
|---|---|---|
| Agent 运行 | AgentRun | Agent 从接受目标到完成、失败、取消或等待审批的一次完整执行 |
| Agent 步骤 | AgentStep | 一次 Agent 运行中的计划、工具调用、观察或输出步骤 |
| 工具 | AgentTool | Agent 可以调用的受控服务能力，不等同于任意 Shell 或数据库访问 |
| 人工审批 | HumanApproval | 对新增信源、停用入口、发布、下架、批量推送等高风险动作的确认 |
| 审计记录 | AuditLog | 记录用户、管理员和 Agent 写操作的不可抵赖信息 |
| 订阅 | Subscription | 用户对主题、实体、来源和时间窗口设置的持续关注规则 |
| 邮件投递 | EmailDelivery | 一次邮件生成、发送、成功、失败或重试的完整记录 |

## 4. 内容策略术语

| 中文术语 | 英文/代码名称 | 定义 |
|---|---|---|
| 全文可展示 | FULLTEXT_ALLOWED | 允许在站内公开展示清洗后的正文 |
| 仅摘要 | SUMMARY_ONLY | 站内公开展示标题、摘要、元数据和原文入口 |
| 仅链接 | LINK_ONLY | 只保存必要元数据并提供原文入口 |
| 私有 RAG 索引 | PRIVATE_RAG | 仅对具备权限的用户可检索；只能用于管理员确认拥有使用权限的上传资料 |
| 展示策略 | display_policy | 决定标题、摘要、正文和原文入口如何对用户展示 |
| 索引策略 | index_policy | 独立决定内容是否允许切片、全文检索和向量化 |
| 公开可见 | PUBLIC | 满足公开准入后可由游客访问 |
| 已发布 | PUBLISHED | 内容已通过自动发布规则或人工审核，可进入对应可见范围 |
| 未证实 | UNCONFIRMED | 来自可信媒体但事实尚未证实，需标记、降权且默认不精选 |
| 已证伪 | DEBUNKED | 已确认错误，默认从列表、搜索和推荐中移除 |
| 一手来源 | PrimarySource | 直接发布事实、产品、模型、论文或代码的官方或原始主体 |
| 独立信源 | IndependentSource | 不属于同一转载链、可对事件形成独立印证的来源 |

## 5. 异步与可靠性术语

| 中文术语 | 英文/代码名称 | 定义 |
|---|---|---|
| 事务发件箱 | Transactional Outbox | 业务数据与待发布事件在同一数据库事务中保存，事务后可靠发布到 RabbitMQ |
| 消费者收件箱 | Consumer Inbox | 消费者记录已处理事件，避免至少一次投递导致重复副作用 |
| 死信交换机 | Dead Letter Exchange | 接收超过重试次数或无法处理消息的 RabbitMQ 交换机 |
| 死信队列 | Dead Letter Queue | 保存需要人工检查或重放的失败消息 |
| 幂等键 | idempotencyKey | 标识一个业务动作，重复投递不得产生重复 LLM、Embedding、邮件或写操作 |
| 关联标识 | correlationId | 串联同一业务链路中的请求与消息 |
| 追踪标识 | traceId | 串联 Web、Java、Python、数据库和消息队列日志的全链路标识 |
| Mock Provider | Mock Provider | 无真实模型密钥时用于基础启动和自动化测试的确定性模拟实现 |
